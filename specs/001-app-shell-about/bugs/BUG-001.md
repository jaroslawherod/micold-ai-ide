# Bug Report: About shows the core library's description, not the application's

**Type**: Regression (introduced by the workspace split, never caught)
**Severity**: Minor — cosmetic, but user-facing and wrong in a dialog whose entire job is identity
**Feature**: 001-app-shell-about (FR-016, contract C5; implicates the 010/021 crate split)
**Reported**: 2026-08-20
**Status**: Open
**Found by**: `quickstart.md` step 4, run for the first time on 2026-08-20 — see
[evidence/B-about-flow-pass.md](../evidence/B-about-flow-pass.md)

## Description

The About dialog's one-line description reads:

> Render-free shared domain model for Micold AI IDE (state, persistence, session/worktree logic,
> wire protocol).

That is `micold-core`'s package description — the internal library's. The application's own
description, in `crates/micold-client/Cargo.toml`, is:

> Thin iced client for Micold AI IDE (feature 010): renders daemon-hosted sessions.

Neither is what a user should read, but the point is that About is not describing the application
at all. It is describing a crate the user has no concept of, in words written for the people who
maintain it ("render-free", "wire protocol").

`Cargo.toml` also carries an `extended-description` written for exactly this audience — "A
local-first, AI-assisted desktop IDE for managing Claude Code worktrees and sessions with an
embedded terminal" — which is presumably the string this dialog was always meant to show.

## Cause

`AppMetadata::from_env()` lives in `crates/micold-core/src/metadata.rs:36-42` and reads
`env!("CARGO_PKG_DESCRIPTION")`. `env!` is expanded **where it is written**, not where it is
called, so the constant is baked in from `micold-core`'s manifest no matter which crate calls it.
`crates/micold-client/src/ui/about.rs:21` calls it from the client and gets the library's string.

Version and license survive the same mistake only by luck: both are `workspace = true`, so every
crate in the tree resolves them to the same value. The description is per-crate, so it does not.

The file's own doc comment shows the author was alive to this class of problem — `APP_NAME` is a
`const` precisely "because Cargo package names cannot contain spaces". When 001 shipped there was
one crate and `env!` was correct; the split into `micold-core` / `micold-client` / `micold-daemon`
(features 010 and 021) moved the manifest out from under it silently.

## Why no test caught it

`metadata.rs`'s tests exercise `resolve()`, the pure function, with arbitrary inputs — they check
the empty→`"unknown"` fallback rule (FR-016) and a 500-character clamp. Nothing asserts *which
manifest* `from_env()` reads, because from inside `micold-core` the answer looks right.

Quickstart step 4 — "Read dialog → shows `Micold AI IDE`, version, license, one-line description"
— is the check that catches it, and it had never been run.

## Recommended fix

Pass the description in from the binary rather than reading it in the library, so the `env!`
expands in the crate that owns the identity:

- `AppMetadata::from_env()` takes the three strings (or the client calls the existing
  `AppMetadata::resolve(...)` directly with its own `env!`s), and
- the client supplies a user-facing description — `extended-description`'s wording, or a `const`
  next to `APP_NAME`, rather than any crate's `description` field.

A regression test can then assert the resolved description is not `micold-core`'s, which is the
property that actually broke.
