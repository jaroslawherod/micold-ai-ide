# Bug Report: All projects' state is lost on restart with no recovery path

**Type**: Spec gap
**Severity**: Critical
**Feature**: 002-project-workspace-management (root storage contract; also implicates
005-worktree-session-terminal, 008-worktree-sidebar-refinement, 010-root-dir-session,
010-regular-terminal-mode)
**Reported**: 2026-07-21
**Status**: Patched
**Patched**: 2026-07-21
**Verification follow-up**: 2026-07-23 — `/speckit.bugfix.verify` found three gaps in the
2026-07-21 patch: (1) `specs/005-worktree-session-terminal/plan.md` had no bugfix note for
FR-020b; (2) `specs/005-worktree-session-terminal/tasks.md` T066 cited bare "T051" for 002's
store-split task, colliding with that file's own unrelated T051 ("Close/stop session"); (3) this
bug's own recommended fix item — surfacing `persist()`/`persist_settings()` write failures instead
of silently discarding them — was never turned into a task; existing **T029** was already checked
complete while claiming exactly that behavior without implementing it. All three fixed: 005/plan.md
bugfix note added; 005/tasks.md T066 reworded to name the file explicitly; T029 reopened
(⚠️ Reopened) and a new **FR-012b** + contract section ("Save-failure surfacing") added to require
visible, non-blocking surfacing of a failed persist.

## Description

After restarting the application, the state of *every* previously open project was lost, and
the application had no way to recover it — every project reverted to a blank slate (no known
projects, no sessions, no worktree display-name overrides, no remembered terminal mode).

All persisted state — the known-projects catalog (002), each project's sessions (005), per-worktree
display-name overrides (008), and each session's AI-CLI/regular-terminal mode (010) — lives in a
single JSON file, `<data_dir>/projects.json`, loaded and saved as one atomic unit
(`src/store.rs`). By the storage contract's own resilience rule, any read/parse failure on that
one file — corruption, a crash mid-write, a failed atomic rename (e.g. cross-device temp
directory), concurrent writers, a hand-edit, a sync-tool conflict — degrades the **entire** file
to an empty `Workspace` (`LoadStatus::Recovered` → `Workspace::empty()`, `src/store.rs:274-306`).
There is exactly one file and one blast radius: a single localized fault destroys every project's
sessions, not just the affected one, and there is no fallback source the app consults afterward.

Two compounding gaps make this worse than "loses one project's list":

1. **No isolation between projects.** A fault has nothing to do with project B, but still empties
   project B's sessions because A and B share one file.
2. **No independent recovery source, even though one exists.** The app already knows how to check
   whether a given session id has a recorded `claude` conversation, via the AI CLI provider's own
   transcript file (`src/provider.rs` `transcript_path`/`has_conversation`,
   `src/main.rs:438-441` `session_has_conversation`) — but this is used only to *prune* sessions
   already present in the (possibly-just-wiped) in-memory list on load (`src/main.rs:420`). It is
   never used to *discover* sessions the app's own store no longer remembers. `claude` itself
   persists a transcript per `(cwd, session-id)` under
   `<claude-config-dir>/projects/<encoded-cwd>/<session-id>.jsonl`, independently of
   `projects.json`. When a project is (re)opened, the app does not scan that independent source
   for the project's supported session locations — its root directory
   (`SessionLocation::Default`, feature 010-root-dir-session) and each of its git worktrees
   (`SessionLocation::Worktree(dir)`) — so real, resumable `claude` conversations on disk are left
   undiscovered and the sessions sidebar simply comes back empty.

Separately, every `persist()`/`persist_settings()` call site swallows the `Result` from
`store.save(...)` (`let _ = store.save(&to_save)`, e.g. `src/main.rs:413,459,1031`), so a failed
write is silent — the user is never told their state failed to save.

## Artifact Traceability

### spec.md (002-project-workspace-management)

- **Affected requirement**: **FR-008** — "The system MUST persist the known-projects list on the
  local filesystem so it survives application restarts." Written when the list held only project
  identity (path/display name/git flag). Features 005/008/010 subsequently persisted live session
  and mode state into the *same* file under this same requirement's storage location, without
  FR-008 (or a new FR) ever being revisited for the higher stakes of what it now guards.
- **Affected edge case**: "Folder gone since it was added" / SC-009 covers *one project's* folder
  going missing — not the store itself failing and taking every project's session state down with
  it. There is no edge case or success criterion for store-level fault isolation.
- **Gap identified**: The spec has no requirement that a storage fault affecting one project must
  not affect another, and no requirement that session state be recoverable from a source other
  than the app's own store.

### contracts/storage-schema.md (002-project-workspace-management)

- **Affected section**: "Compatibility & resilience rules" — "Unparseable / corrupt file →
  degrade to an empty list rather than crashing... (research R8; SC-009)."
- **Impact**: This is the literal root cause. It was a reasonable trade-off in 002, when the file
  held nothing but a re-browsable folder list (losing it costs the user a few clicks). Three later
  contracts explicitly reused this exact clause as precedent while enlarging what it protects:
  - `specs/005-worktree-session-terminal/contracts/storage-schema.md:61` — "Missing/corrupt store
    → empty, no crash (existing `LoadStatus::Recovered` behavior reused)" — now covers live
    session identity.
  - `specs/008-worktree-sidebar-refinement/contracts/persistence.md` — worktree display-name
    overrides added to the same file under the same recovery rule.
  - `specs/010-root-dir-session/contracts/storage-schema.md:28-31` and
    `specs/010-regular-terminal-mode/contracts/persistence-schema.md:30` — root-dir sessions and
    per-session terminal mode, same rule again.
  None of these four extensions revisited whether whole-file degrade-to-empty was still the right
  call once the file's contents graduated from "a list you can rebuild by re-browsing" to "live,
  otherwise-unrecoverable session state for every open project."

### 005-worktree-session-terminal/spec.md

- **Affected requirements**: **FR-020/FR-020a/FR-021/SC-008** — already establish that the app can
  detect a recorded `claude` conversation via transcript existence, and use it to *prune* stale
  entries from the persisted list (bugfix BUG-001 in that feature). They stop short of using the
  same detection to *reconstruct* sessions the store has lost track of.
- **Gap identified**: No requirement that, on opening a project, the app reconcile its persisted
  session list against `claude`'s own transcripts for that project's supported session locations
  (root directory + worktrees) and restore any session with a transcript but no persisted record.

### 010-root-dir-session/spec.md

- **Affected concept**: `SessionLocation::Default` (the project root directory) as a session
  location co-equal with `SessionLocation::Worktree(dir)`.
- **Impact**: Any reconciliation/discovery fix must scan **both** supported locations — root
  directory and worktrees — not just worktrees, per this feature's introduction of root-dir
  sessions as a first-class location.

### tasks.md

- **Affected tasks**: **T026** (002) implemented `JsonFileStore` as a single whole-catalog
  load/save; **T044** (005) extended it in place rather than splitting storage, explicitly to
  avoid a `schema_version` bump — reasonable for compatibility, but it's the point at which
  fault-isolation should have been reconsidered and wasn't.
- **False completions**: None — all cited tasks correctly implement what they specified. The
  specs themselves under-specified fault isolation and recovery, so no task is "wrong."
- **Missing tasks**: (a) split `projects.json` into a lightweight catalog plus one state file per
  project, keyed by a stable identifier derived from the project's canonical path; (b) on project
  open, scan the AI CLI provider's transcript directory for the project's root directory and each
  worktree, and reconstruct any `Session` missing from the persisted/recovered state; (c) surface
  `persist()`/`persist_settings()` write failures to the user instead of discarding the `Result`.

## Root Cause Analysis

Two independent oversights compound into total, unrecoverable state loss:

1. **Architectural drift without re-evaluation.** Research R8's "corrupt → wipe whole file to
   empty" was a deliberate, reasonable trade-off for a lightweight, easily-rebuilt known-projects
   list. Four subsequent features (005, 008, 010-root-dir-session, 010-regular-terminal-mode) each
   added materially higher-stakes state to the *same* shared-fate file and each cited the *same*
   R8 clause as established precedent, without any of them asking whether the trade-off still held
   once the file's contents were "everything," not just "a list." The blast radius grew four times
   over while the recovery strategy never changed.
2. **An existing recovery signal was never wired to restore, only to prune.** The app already has
   the exact mechanism needed to rebuild lost session state — `claude`'s independent, per-`(cwd,
   session-id)` transcript files — but only ever uses it defensively (drop entries with no
   transcript) rather than affirmatively (find transcripts with no entry). Combined with (1), a
   store-level fault has no fallback: the one file that held everything is gone, and the one other
   place the same information independently lives (`claude`'s own transcripts) is never consulted.

## Recommended Fix

1. Run `/speckit.bugfix.patch` to:
   - Amend `contracts/storage-schema.md` (002) to split persistence into a small `projects.json`
     catalog (path, display name, git flag, `last_active`) plus one state file per project
     (sessions, worktree display-name overrides, terminal mode), addressed by a stable identifier
     derived from the project's canonical path, so a corrupt/missing per-project file degrades
     only that project to empty — never the catalog or any other project.
   - Add a requirement (005 and/or 010-root-dir-session) that opening a project reconciles its
     session list against the AI CLI provider's transcripts for the project's root directory and
     every worktree, restoring any session with a transcript but no persisted record.
   - Note the silent `let _ = store.save(...)` failure swallow for a non-fatal but visible error
     surface.
2. Run `/speckit.bugfix.verify` to confirm the amended contracts stay consistent across
   002/005/008/010-root-dir-session/010-regular-terminal-mode.
3. Resume `/speckit.implement` (or a dedicated fix task) to apply the per-project storage split
   and the transcript-based reconciliation scan.
