- **Input**: A projects.json or a project-state file that does not carry its schema_version number is rejected on load, moved aside to a .bak file, and replaced by defaults with nothing said — so the user's project list, or one project's saved state, silently resets. StoredCatalog::schema_version at crates/micold-core/src/store.rs:88 and StoredProjectState::schema_version at crates/micold-core/src/store.rs:389 are both bare u32 with no serde default, while every other field of those documents tolerates absence. This is the same defect that PR #412 (merge 23a0e0ee) just fixed one file away for settings.json: see specs/003-material-design-layout/bugs/BUG-003.md and its FR-022, which chose serde(default) with 0 meaning 'the document named no version', on the grounds that nothing reads the field. The likely owning spec here is feature 002 and its storage-schema contract; confirm that from the contract rather than assuming it, and check whether that contract makes the version field required the way 003's did. The fix is expected to be small: a default for each field, a regression test per document proving a version-less file loads its real values and is not recovered, and whatever contract amendment the owning spec needs. Do not add a migration path the repository does not have.
