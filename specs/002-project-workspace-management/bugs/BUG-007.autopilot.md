| M1 | A r2 | Root cause: make the client's launch read non-renaming and leave recovery to the daemon | The client's read is the one a cold launch meets first and the one whose status FR-012d reports; a read-only client load would report a file the daemon then moves under a name the client cannot know, and on a warm launch leave the damaged file for a later cold launch. The write-back at connect and stop closes the loss window within this design; a redesign of who recovers belongs with 010 C1/C4's protocol follow-up |
| M1 | A r2 | The read-error branch now moves aside an intact file on EACCES/EIO | Chosen trade-off (review A r1 raised the opposite): left in place, the next save writes the empty catalog over it and the list is destroyed; moved aside, it is kept and named.
