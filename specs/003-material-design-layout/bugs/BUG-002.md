# Bug Report: The known-projects row drops its project name and clips its actions in a narrow window

**Type**: Implementation defect
**Severity**: Medium
**Feature**: 003-material-design-layout
**Reported**: 2026-08-21
**Status**: **Fixed** — a known-projects row too narrow for its name and its actions now moves the
actions beneath the name, and the name elides with `…` on one line instead of wrapping or vanishing.

**Fixed**: 2026-09-13 — Phase 7 (T036–T039). Gated by
`crates/micold-client/tests/known_projects_reflow.rs` (at 640dp and 440dp) and the `Reflow` unit
tests in `crates/micold-client/src/ui/cdk/reflow.rs`.

**Patched**: 2026-09-13 — FR-016 amended, plan.md annotated, T036–T039 added.

**Found by**: T015 / T033 — the quickstart §3 manual walkthrough, run for the first time

## Description

`quickstart.md` §3 asks: *"Resize the window small: content reflows and stays usable without
clipping."* It does not. As the window narrows, each Known-projects row degrades by **losing
content**, not by reflowing:

| Window width | What the row shows |
|---|---|
| ≥ ~880 px | check marker · **project name** · `git` badge · Open · Rename · Forget — correct |
| ~810–870 px | the name wraps to two lines and the **second line is cut off** by the row's fixed height ("Gone Away" renders as "Gone" plus a sliced "Away") |
| ≤ ~800 px | the **project name is gone entirely** — no ellipsis, no tooltip. Every row is now anonymous: two projects are distinguishable only by their marker icon |
| ≤ ~760 px | **Forget** loses its label, then its icon, ending as an **empty outlined pill** |
| ≤ ~620 px | **Rename** disappears too; the remaining empty pill **overflows the card's right edge** and is clipped by it |

`../evidence/s3-reflow.png` is the ladder, one strip per width, cropped at identical geometry.

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 1 — the Material layout.
- **Affected requirements**:
  - **FR-016** (`spec.md:157-158`) — "The layout MUST respond to window resizing and preserve
    usable spacing at small window sizes **without clipping or overlapping content**." Both
    halves fail: content is clipped (the wrapped name, the overflowing pill) and content is
    dropped (the name, the button labels, the button icon).
  - **FR-012** (`spec.md:148-150`) — the known-projects list must preserve "the active marker,
    the 'git' badge, the unavailable state, and the Open / Rename actions". At 620 px Rename is
    not rendered at all, so the list no longer preserves it.
  - **Edge case** (`spec.md:112-113`) — "What happens to the layout at very small window sizes?
    Content remains usable — surfaces reflow and spacing is preserved rather than clipping or
    overlapping." This is the answer the spec gave itself, and it is not what ships.

### Not covered by any test

The layout gates in `crates/micold-client/tests/` resolve rectangles at the default window size.
Nothing exercises a narrow window, so nothing caught this.

## Cause

`crates/micold-client/src/ui/shell.rs:113-140`. The row is a plain `row![]` whose only flexible
child is the name:

```rust
entry = entry.push(
    Text::new(project.display_name.clone(), TypeRole::Body, r).width(Length::Fill),
);
...
let entry = entry.push(reopen).push(rename).push(forget);
```

The three buttons are laid out at their intrinsic width. When the row is narrower than their sum,
the `Length::Fill` child is the only one that can give, so it shrinks — first to a wrapping,
vertically clipped two-line label, then to zero. Past that point the buttons themselves exceed the
available width and are clipped by the surrounding `Surface`. There is no minimum width on the
name, no breakpoint that moves the actions onto a second line, and no icon-only fallback with a
tooltip.

The identical pattern appears for the unavailable row, which is why its Forget button degrades one
step ahead of the available row's: "Unavailable" is a wider button than "Open".

## Recommended Fix

*(Applied 2026-09-13 — see "Decision" below.)* Not attempted in the walkthrough, whose job was to find
it. Two directions, either of which satisfies
FR-016:

1. **A breakpoint.** Below a threshold width, wrap the row: name and badges on the first line,
   the action cluster on the second. This keeps every label readable and is what "reflows" means.
2. **A deliberate collapse order.** Give the name a minimum width and elide it with `…`; collapse
   the *actions* to icon-only (with tooltips, which the app already has) rather than letting them
   silently lose their icon and become blank pills.

Whichever is chosen, an empty unlabelled button is never an acceptable end state — it is a control
the user cannot identify, and at 620 px it is also partly off its own card.

## Decision

**Direction 1, the breakpoint, with the name elided on one line.** The report left the choice open.
Direction 1 is the smaller fix: it needs no tooltips and no icon-only button variant, and it keeps
every label readable, which is what FR-012 and FR-016 ask for. Direction 2's elided name is kept
because a single line still has to end somewhere, but its icon-only collapse is not, since an
icon-only Forget is only one step better than the blank pill this report describes.

How it is built:

- **`cdk::reflow::Reflow`**, a new layout-only behaviour-layer widget with two children. It lays the
  trailing child (the actions) out at its one-line width, and puts it beside the leading child
  (markers, name, `git` badge) only while the leading child still gets at least `lead_min`.
  Otherwise the actions go on the line beneath, starting at the leading edge. It has no appearance,
  so it lives in `cdk` and passes `cdk_no_appearance`, with a `showcase_completeness` exemption
  explaining that there is nothing to show.
- **`ROW_LEAD_MIN` = 240dp** in `shell.rs`. That is room for the markers, the badge and about 15
  characters of name. Below it, stacking reads better than a name cut to a few letters.
- **The name is an `Ellipsized` label** at the body role, the precedent the rest of the library
  already uses for one-line text. Its height is one line, so the row never cuts a wrapped second
  line.
- **The actions are a wrapping row**, so a window too narrow even for the three buttons on one line
  wraps them rather than clipping them.
- **The decision is per row.** An unavailable row, whose "Unavailable" button is the widest, can
  stack while an available row beside it does not. The rows' heights then differ, which is honest:
  each row shows everything it has.

Why a new widget rather than iced's own `Row::wrap()` on the whole row: a wrapping row breaks by
each child's own width and has no way to keep a minimum for one flexible child, so it cannot say
"move the actions once the name would get less than 240dp". The break has to be decided by the
name's remaining width, which takes a layout of its own.

At the default 1280×800 window every row still shares one line. The regenerated layout snapshot
changes only the known-projects rows. Every button keeps its box, and the name keeps its x and width.
The name's height goes from 20.0 to 18.2, the one-line height of `Ellipsized`, so its centred box
moves 0.9dp down. Each row gains two container boxes: the identity half and the action cluster.
