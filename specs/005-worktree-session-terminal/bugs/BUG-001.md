# Bug Report: Empty sessions are persisted and resumed on restart

**Type**: Spec gap
**Severity**: High
**Feature**: 005-worktree-session-terminal
**Reported**: 2026-07-16
**Status**: Patched
**Patched**: 2026-07-16

## Description

After restarting the app, the embedded terminal shows an error like
`No conversation found with session ID: <uuid>` for sessions that were never actually used.

An "empty" session is one the user started but never sent any input to, so `claude` never
recorded a conversation transcript for that session id. On restart the app restores the
persisted session and launches `claude --resume <id>`; because `claude` has no conversation for
that id, it errors. The user expects empty/never-used sessions to be discarded, not preserved
and resumed.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 3 — Start a session and interact with the embedded terminal (P1).
- **Affected requirements**:
  - **FR-020**: "System MUST persist each session's identity (including a reference to the
    underlying `claude` session id) and its association to a worktree locally, and MUST restore
    session entries in the sidebar across application restarts." — persists **all** sessions
    unconditionally.
  - **FR-021**: resume a persisted session via `claude --resume <session-id>` on reopen.
  - **FR-023a**: restore + resume a project's sessions on reopen.
  - **SC-008**: "After an application restart, 100% of previously persisted sessions reappear …
    and reopening one resumes its prior `claude` conversation via `claude --resume`." — assumes
    every persisted session has a prior conversation.
- **Gap identified**: The spec never distinguishes an **empty session** (no `claude` conversation
  recorded) from a real one. It mandates persisting and resuming *all* sessions, which makes a
  never-used session resume-fail after restart. The persistence requirements need an explicit
  exclusion: only sessions with a recorded `claude` conversation are persisted/resumed.

### plan.md
- **Affected sections**: "Storage" (Technical Context) and the session-persistence design.
- **Impact**: The persistence rule must state that empty sessions are not written to the store,
  and that the store is filtered on save + pruned on load. Detection of "empty" is a
  `claude`-transcript-existence check (`<claude>/projects/<encoded-cwd>/<session-id>.jsonl`;
  encoded-cwd = worktree path with every non-alphanumeric char replaced by `-`; honors
  `CLAUDE_CONFIG_DIR`).

### contracts/storage-schema.md
- **Affected section**: "What is persisted" / "Load / restore behavior".
- **Impact**: Add that sessions without a `claude` conversation transcript are excluded on save
  and pruned on load.

### tasks.md
- **Affected tasks**:
  - **T040** — session store roundtrip (persist/load). Needs an added case: empty sessions are
    not persisted.
  - **T044** — extend `store` to persist/load sessions. Needs the empty-session filter at the
    I/O boundary (the transcript check is filesystem I/O, so it lives in the binary/persist path,
    not the pure store).
  - **T053 / T023 (boot restore)** — restore path must prune empty sessions on load.
- **False completions**: none — the affected tasks did not specify empty-session handling, so they
  were not "wrong", they were under-specified. A follow-up task captures the new behavior.
- **Missing tasks**: a new task for "exclude empty sessions from persistence + prune on load,"
  with a test.

### Related implementation-only defect (not a spec change)
- The terminal rendered raw ANSI/VT escape sequences as literal text instead of interpreting
  them. This is **implementation drift** against **FR-012/FR-013** (an interactive terminal
  running `claude`), from task **T047** having been left incomplete (raw monospace instead of a
  VT emulator). Fixed by feeding the PTY stream through `alacritty_terminal` (a VT emulator) and
  rendering the interpreted grid. No spec change required; T047 is now genuinely implemented.

## Root Cause Analysis

**Spec oversight.** The persistence requirements (FR-020/021/023a, SC-008) were written assuming
every session is worth persisting and resuming. They did not account for a session the user
opens but never interacts with, for which `claude` records no conversation — so resuming it is
guaranteed to fail. The clarification sessions covered restore semantics but not the empty-session
case.
