# Bug Report: Session name is out of sync with the AI CLI's session name

**Type**: Implementation drift (primary) + Spec gap (provider abstraction)
**Severity**: High
**Feature**: 005-worktree-session-terminal
**Reported**: 2026-07-17
**Status**: Patched
**Patched**: 2026-07-17

## Description

The name shown for a session in the app (sidebar label / session store) never matches the
session name/title that the underlying AI CLI (`claude`) assigns to that conversation. The
sidebar keeps showing the `Pending` placeholder ("New session"), or a stale persisted title,
even after `claude` has recorded an `ai-title` for the conversation.

**Observed:** every session sub-item reads "New session" indefinitely; the app-side name and the
`claude`-side session name diverge and never reconcile.

**Expected (FR-011a):** the label is extracted from the AI CLI (its session name/title), shown as
a placeholder until available, then updated once the provider assigns/changes a name, and kept in
sync thereafter.

### Additional requirement from the reporter — provider abstraction

The reporter also asks that the fix **not hard-code `claude`**. The label-sync mechanism (and the
surrounding session model, contract, and persistence) should be expressed against an abstract
"AI CLI provider" concept so that other AI CLI providers can be supported in a future version
without reworking the sync path. Today `claude` is named directly across the spec, contracts, code
comments, and the message/label types.

## Root Cause Analysis

**Incomplete implementation (implementation drift against FR-011a).** Task **T054** — "Best-effort
session label from `claude` `ai-title` JSONL, updating `Pending` → `Named`" — was never
implemented (it is marked `[ ]` in `tasks.md`, and the completion notes at `tasks.md:272` state
"session labels stay at the `Pending` placeholder; reading the `claude` `ai-title` JSONL to
populate `Named(..)` is not yet implemented").

Concretely, the plumbing exists but the *producer* is missing:

- `Message::SessionTitleUpdated { id, title }` is **defined** (`src/app.rs:226`).
- It is **handled** — the reducer calls `session.set_title(title)` (`src/app.rs:518-521`), which
  sets `SessionLabel::Named` (`src/session.rs:146-149`).
- It is **covered by a test** (`tests/app_state.rs:100`).
- But **no production code ever emits it.** `grep` for `SessionTitleUpdated` / `ai-title` /
  `aiTitle` across `src/` finds only the definition, the handler, and the test — never a read of
  the transcript. The `TerminalTick` poll (`src/main.rs:650-656`) pumps PTY bytes and handles
  process exits but never reads the `ai-title` record described in `contracts/claude-cli.md`
  ("Session label extraction (best-effort, FR-011a)").

Because the producer is absent, `set_title` is never called at runtime, so the label is stuck at
whatever it was seeded with (`Pending`, or a stale value loaded from the store).

**Secondary — spec gap (abstraction).** The spec, contract, data model, and code all name `claude`
directly (FR-011a/FR-020/FR-021, `contracts/claude-cli.md`, `data-model.md`, and the doc-comments
/ types in `src/session.rs`). There is no abstraction seam for "the AI CLI provider," so the
missing sync logic — and everything around it — is written specifically for `claude`.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 3 — Start a session and interact with the embedded terminal (P1).
- **Affected requirements**:
  - **FR-011a** (`spec.md:127`): "System MUST label each session in the sidebar using the session
    name/title extracted from `claude` … MUST update the label once the name becomes available.
    The extracted name MUST be persisted alongside the session id." — this is the requirement that
    is not implemented (no reader) and that hard-codes `claude`.
  - **Clarifications** (`spec.md:24`): "The session label is extracted from `claude` (its session
    name/title) … A placeholder is shown until `claude` provides a name." — same hard-coding.
  - **FR-020 / FR-021 / FR-023a** and the **Session** key-entity definition (`spec.md:139-152`):
    all reference the "`claude` session id" / "`claude`-provided session name/title" directly;
    these are the spots the provider abstraction must touch.
- **Gap identified**:
  1. No requirement forces the label to be actively *reconciled* with the provider's current
     session name while a session runs (FR-011a says "update … once available" but the flow was
     never built).
  2. No provider-abstraction requirement: every mention of the AI CLI is literally `claude`.

### plan.md
- **Affected sections**: Technical Context (the `claude` CLI integration) and the
  session-label/persistence design.
- **Impact**: The plan must (a) describe the concrete title-sync path (poll/read the provider's
  transcript → emit a title-updated message → update + persist the label), and (b) introduce an
  "AI CLI provider" seam so the transcript location, id flag, resume flag, and title-record format
  are provider-specific details behind a single abstraction, with `claude` as the first
  implementation.

### contracts/claude-cli.md
- **Affected sections**: "Session label extraction (best-effort, FR-011a)" and the whole file's
  `claude`-specific framing.
- **Impact**: Generalize into an **AI-CLI-provider contract** (provider-neutral: launch, resume,
  id ownership, transcript location, title-record extraction), with the current `claude` v2.1.210
  specifics as one concrete provider profile. The title-extraction section must be the contract
  the new reader implements.

### data-model.md
- **Affected sections**: the `Session` entity's `claude` session id / `claude`-provided title
  fields.
- **Impact**: Rephrase in provider-neutral terms (e.g. "AI CLI session id", "provider-supplied
  session title"), keeping the on-disk schema backward compatible with existing persisted stores.

### tasks.md
- **Affected tasks**:
  - **T054** (`tasks.md:156`, currently `[ ]`): "Best-effort session label from `claude`
    `ai-title` JSONL, updating `Pending` → `Named` (FR-011a, claude-cli.md)". **This is the
    unbuilt task at the heart of the bug** — it must be implemented (with a test) and its
    completion note (`tasks.md:272`) updated.
- **False completions**: none. T054 was honestly left `[ ]`; the defect is that the feature shipped
  with a visible, spec'd capability unimplemented.
- **Missing tasks**:
  1. Implement the provider title reader + emit `SessionTitleUpdated` on the terminal poll
     (completes T054), with a headless test proving `Pending → Named` and re-sync on change.
  2. Introduce the AI-CLI-provider abstraction (trait/type) and route the `claude` specifics
     (id flag, resume flag, transcript path encoding, title-record parsing) through it; rename
     `claude`-specific identifiers/comments/messages to provider-neutral names where they are part
     of the public model.
