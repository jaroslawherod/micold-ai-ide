# Bug Report: Selecting a session does not auto-focus its terminal

**Type**: Spec conflict (desired auto-focus vs. FR-010 explicit-focus-only) + minor implementation drift
**Severity**: Medium
**Feature**: 006-real-terminal-emulator (focus model); also touches 005-worktree-session-terminal (session selection)
**Reported**: 2026-07-17
**Status**: Patched
**Patched**: 2026-07-17

## Description

When the user selects (or starts) a session, the embedded terminal for that session is displayed
but does **not** receive input focus. To type into `claude` the user must first click the terminal
pane. The expectation is that selecting a session immediately focuses its terminal so the user can
perform actions right away, without the extra click.

**Observed:** select a session in the sidebar → its terminal shows on the right, but keystrokes go
to the app (the terminal is unfocused). The user must click the terminal pane before any input
reaches the `claude` process.

**Expected:** selecting or starting a session makes that session's terminal the focused terminal,
so keyboard input reaches its `claude` process immediately. The existing ways to release focus
(click outside the pane, the reserved `Ctrl+Shift+E` / `Cmd+Shift+E` chord, the header affordance)
and the lifecycle write-gating (bytes only delivered while the session is `Running`) are unchanged.

### Why the current behavior exists

This is not an accidental omission — feature 006 deliberately specified focus-on-explicit-click
only, to stop app shortcuts being swallowed merely because a session is open (User Story 3). The
new requirement — auto-focus on selection so the user can work immediately — is aligned with
feature 005's payoff (User Story 3: "start a session and interact with the embedded terminal") and
directly conflicts with 006's FR-010 and the focus-model contract. Resolving it requires amending
the 006 spec, not just the code.

## Root Cause Analysis

**Spec conflict (primary).** Feature 006 mandates that terminal focus is acquired *only* by an
explicit click and that selecting a session *clears* focus:

- **FR-010** (`spec.md:142`): "The terminal MUST gain focus **only** through an explicit user
  action (for example, clicking the terminal)."
- **focus-model.md** transition table (`contracts/focus-model.md:15,17`): `unfocused → focused`
  only via `Message::TerminalFocused` (click); and `SessionSelected` / close / project-switch →
  `unfocused` ("re-focus is a fresh explicit action").
- **T025** (`tasks.md:158`): "`SessionSelected`/close/project-switch **clear** focus (FR-010,
  FR-011)."

So the app behaves as specified — the spec itself prescribes the opposite of the desired UX.

**Minor implementation drift (secondary).** The `SessionSelected` reducer branch
(`src/app.rs:556-558`) sets `active_session` but does **not** set `terminal_focused = false`, even
though T025 / focus-model.md say `SessionSelected` should clear focus. In practice focus still ends
up cleared because clicking a sidebar item is a click *outside* the pane, which publishes
`Message::TerminalFocusReleased` (`src/ui/material/terminal_pane.rs:355-360`). Net effect matches
the spec (unfocused after select), which is why the user sees "must click to type."

## Artifact Traceability

### spec.md (006-real-terminal-emulator)
- **Affected user story**: User Story 3 — "Keys reach the terminal only when it is focused" (P2).
- **Affected requirements**:
  - **FR-010** (`spec.md:142`): the "focus only through an explicit user action" clause is the one
    that forbids auto-focus. Must be amended to allow/require focus to follow session
    selection/start while keeping manual focus + release.
  - **FR-009** (`spec.md:141`) and **US3 rationale** (`spec.md:62-64`): the "app shortcuts work
    whenever a session is open" expectation shifts — after auto-focus, app shortcuts require a
    focus release first. This trade-off must be stated explicitly.
  - **SC-003** (`spec.md:185`) still holds unchanged: while *unfocused*, 0% of keys reach the
    process. Auto-focus changes the *initial* focus state after selection, not the routing rule.
- **Gap/conflict identified**: there is no requirement that a session becoming the displayed
  session focuses its terminal; the existing FR-010 actively prohibits it.

### contracts/focus-model.md (006)
- **Affected sections**: "Transitions" table (`:13-17`).
- **Impact**: change the `SessionSelected → unfocused` row (and add `SessionStarted`) to
  `→ focused`; add an `unfocused → focused` trigger for "session becomes the displayed session."
  Keep all release transitions and the routing/write-gating rules intact.

### plan.md (006)
- **Affected sections**: the focus-model / key-routing design narrative.
- **Impact**: document that selecting/starting a session sets `terminal_focused = true` for the
  newly displayed session, and that release mechanisms and `Running`-only write-gating are unchanged.

### tasks.md (006)
- **Affected tasks**:
  - **T025** (`tasks.md:158`, `[X]`): "`SessionSelected`/close/project-switch clear focus" — the
    `SessionSelected` part is now inverted (should *set* focus). Close / project-switch should still
    clear focus.
- **False completions**: none — T025 was completed against the old contract.
- **Missing tasks**:
  1. Update the reducer so `SessionSelected` and `SessionStarted` set `terminal_focused = true`
     (auto-focus the newly displayed session), with a pure test asserting it.
  2. Update `tests/terminal_focus.rs` / `tests/app_state.rs` expectations for the new
     select-focuses-terminal behavior (base state still defaults `terminal_focused = false`).
  3. Ensure clicking a sidebar item still results in the *selected* session's terminal being
     focused (the click-outside `TerminalFocusReleased` must not race ahead of `SessionSelected`).
  4. Update focus docs in `docs/user-guide/worktrees-and-sessions.md` (T027) to describe
     auto-focus-on-select and how to release focus.

### spec.md (005-worktree-session-terminal) — related
- **User Story 3** ("Start a session and interact with the embedded terminal") and **SC-004/SC-005**
  express the "start working immediately" intent that motivates this change. No 005 requirement
  currently mandates focus behavior, so 005 needs at most a cross-reference; the normative change
  lives in 006.

## Recommended Fix

1. Run `/speckit.bugfix.patch` to update the 006 artifacts:
   - **spec.md**: amend FR-010 to make focus follow the displayed session (auto-focus on
     select/start) while preserving explicit focus + release; note the FR-009/US3 trade-off; add a
     Clarifications entry.
   - **contracts/focus-model.md**: flip the `SessionSelected → unfocused` transition to
     `→ focused`, add `SessionStarted → focused`, keep release transitions and gating.
   - **plan.md** / **tasks.md**: reflect the auto-focus path; adjust T025 and add the reducer/test
     tasks above.
2. Run `/speckit.bugfix.verify` to confirm artifact consistency across spec/plan/tasks/contracts.
3. Run `/speckit.implement` to apply the code fix: set `terminal_focused = true` in the
   `SessionSelected` and `SessionStarted` reducer branches (`src/app.rs`), ensure the sidebar-click
   focus wins over click-outside release, and add/adjust headless tests
   (`tests/terminal_focus.rs`, `tests/app_state.rs`) proving select/start focuses the terminal and
   that release still works.
