# Bug Report: Touchpad scrolling is dead under Wayland — sub-line wheel deltas are discarded

**Type**: Spec gap (FR-016 is silent on pixel-precision scroll deltas) → resulting implementation defect
**Severity**: High
**Feature**: 006-real-terminal-emulator (sizing & scrollback)
**Reported**: 2026-07-20
**Status**: Patched
**Patched**: 2026-07-20

## Description

The embedded terminal cannot be scrolled with a touchpad on a Wayland session. Two-finger scrolling
produces no viewport movement at all, and because the scrollbar is only shown while
`display_offset != 0` (FR-016a), the scrollbar never appears either — so the pane looks like it has
no scrollback whatsoever.

**Observed** (Ubuntu 26.04, Wayland/GNOME, high-resolution touchpad): two-finger scroll over the
terminal pane does nothing. A discrete mouse wheel still scrolls correctly.

**Expected**: two-finger touchpad scrolling moves the viewport through the scrollback, as it does in
a reference terminal. The same session's Ptyxis (VTE 0.84) scrolls correctly under identical
conditions, confirming the input events are being delivered by the compositor.

### Root mechanism

`src/ui/material/terminal_pane.rs:585-590` converts the wheel delta to whole lines and then drops
the event when the result is zero:

```rust
Event::Mouse(mouse::Event::WheelScrolled { delta }) if cursor.is_over(bounds) => {
    let lines = match delta {
        mouse::ScrollDelta::Lines { y, .. } => y.round() as i32,
        mouse::ScrollDelta::Pixels { y, .. } => (y / metrics.height).round() as i32,
    };
    if lines != 0 {
```

There is **no sub-cell residual accumulator** — `PaneState` (`terminal_pane.rs:28-38`) holds no
remainder field, and no accumulation exists anywhere in `src/ui/`. Each event is quantized
independently and the fraction is thrown away. A high-resolution touchpad emits many small deltas of
a few pixels each; every delta whose magnitude is under half a cell height rounds to `0`, fails the
`lines != 0` guard, and is discarded without even being `Captured`. The fractions never sum to a
line, so no amount of scrolling ever moves the viewport.

### Why this is session-protocol dependent

- **X11**: touchpad scroll is delivered as legacy discrete button-4/5 events, which iced surfaces as
  `ScrollDelta::Lines { y: ±1.0 }`. `.round()` yields ±1 and scrolling works.
- **Wayland**: libinput delivers high-resolution axis events, which iced surfaces as
  `ScrollDelta::Pixels` with small per-event values. Every one rounds to zero and scrolling is
  completely non-functional.

This makes the defect invisible on X11 and total on Wayland. Wayland is the default session on
Ubuntu 25.10+ and on most current GNOME/KDE distributions, so the majority of Linux users are
affected. The same `ScrollDelta::Pixels` path is used for macOS trackpads and precision-touchpad
devices on Windows, so this is very likely a cross-platform defect (Constitution Principle VI:
cross-platform parity) rather than a Linux-only one.

## Root Cause Analysis

**Spec gap (primary).** FR-016 (`spec.md:163`) specifies *what* must scroll and *by what input*, but
never specifies *how a scroll delta maps to lines*:

> "Scrolling MUST be driven at least by the mouse wheel."

The phrase "at least by the mouse wheel" sets a floor without naming touchpad or pixel-precision
input, and nothing in the spec requires that sub-line deltas be **accumulated rather than
discarded**. With no such requirement, quantize-and-drop is a conforming implementation. The
contract is equally silent: `contracts/terminal-render-input.md:49` says only "else scrolls local
scrollback", and `:69` lists the test as "wheel→scroll" with no delta-granularity rule.

This is a spec gap rather than implementation drift — the code satisfies the spec as written. The
spec was authored with a discrete wheel in mind (one notch = N lines) and did not anticipate
continuous, sub-line scroll sources.

**Test blind spot (secondary).** T028 (`tasks.md:178`) specified the failing test as "wheel delta →
`Scroll(n)`", which was implemented against whole-line deltas only. No test exercises
`ScrollDelta::Pixels`, and no test asserts that repeated sub-line deltas eventually produce a scroll.
The defect was therefore invisible to CI on every platform.

## Artifact Traceability

### spec.md (006-real-terminal-emulator)
- **Affected user story**: User Story 4 — "Correct sizing, resize, and scrollback" (P3),
  `spec.md:82-88`; acceptance scenario 3 (`spec.md:94`): "When the user scrolls back, Then earlier
  output is shown."
- **Affected requirements**:
  - **FR-016** (`spec.md:163`) — primary. "Scrolling MUST be driven at least by the mouse wheel"
    names no continuous/pixel-precision input source and imposes no accumulation rule. Must be
    amended to require touchpad/precision scrolling and to mandate that sub-line deltas accumulate
    rather than being discarded.
  - **FR-016a** (`spec.md:164`) — consequential. The scrollbar is specified to be hidden at the live
    bottom, so the FR-016 defect makes the scrollbar permanently invisible, compounding the symptom
    into "the terminal appears to have no scrollback."
  - **FR-013a** (`spec.md:156`) — adjacent. It requires forwarding "wheel/scroll" to a
    mouse-reporting process. The same quantization applies on that path
    (`terminal_pane.rs:591-605` emits one report per whole line), so a mouse-reporting process
    receives no wheel reports from a touchpad either. Any accumulation rule must cover both branches.
- **Gap identified**: no requirement states how a scroll delta of less than one line must be
  handled. Nothing forbids discarding it, so the implementation does.

### contracts/terminal-render-input.md
- **Affected sections**: `:49` (wheel → alt-screen forward vs local scrollback) and `:69` (listed
  widget test "wheel→scroll").
- **Impact**: add a delta-handling rule specifying that line-based and pixel-based deltas are both
  supported, that pixel deltas are divided by the cell height, and that the fractional remainder is
  retained in widget state across events until it accumulates to a whole line. Specify that the
  residual resets on direction change and is per-pane.

### plan.md (006)
- **Affected sections**: the input-translation narrative (`plan.md:11`, the "translates iced
  key/mouse events into terminal actions" design) and Constitution check VI (`plan.md:45`), which
  claims "resize, scroll, and copy/paste are platform-agnostic" — untrue as implemented, since
  scroll behavior silently depends on the session protocol's delta representation.
- **Impact**: document the residual accumulator as part of the widget's event translation, and
  correct the parity claim.

### tasks.md (006)
- **Affected tasks**:
  - **T028** (`tasks.md:178`, `[X]`): "wheel delta → `Scroll(n)`" — the test scope is too narrow; it
    covers only whole-line deltas.
  - **T030** (`tasks.md:183`, `[X]`): "Wire scrolling: `TerminalPane` wheel/PageUp-Down →
    `TermAction::Scroll`" — the implementation this produced is the defect site.
- **False completions**: none in the strict sense — both tasks satisfied the contract as written.
  They are incomplete only against the amended FR-016 proposed here.
- **Missing tasks**:
  1. Add a `scroll_residual: f32` (or equivalent) to `PaneState`; accumulate pixel deltas, emit
     `trunc()` whole lines, retain the fraction; reset on direction change.
  2. Apply the same accumulation to the mouse-reporting branch so a touchpad generates wheel reports
     for a mouse-reporting process (FR-013a).
  3. Add gui-gated tests in `tests/terminal_resize_scroll.rs`: a single sub-line `ScrollDelta::Pixels`
     event produces no scroll but is retained; N such events summing past one cell height produce
     exactly one line of scroll; direction reversal does not leak a stale residual; `ScrollDelta::Lines`
     behavior is unchanged.
  4. Update `docs/user-guide/worktrees-and-sessions.md` (T031) to state that touchpad/precision
     scrolling is supported.

## Recommended Fix

1. Run `/speckit.bugfix.patch` to update the 006 artifacts:
   - **spec.md**: amend **FR-016** to require scrolling by mouse wheel *and* touchpad/precision
     input, and to mandate that deltas smaller than one line accumulate across events rather than
     being discarded; add a Clarifications entry recording the discrete-vs-continuous distinction.
   - **contracts/terminal-render-input.md**: add the explicit delta→lines rule with residual
     retention, covering both the local-scrollback and mouse-report branches.
   - **plan.md**: note the accumulator in the input-translation design; correct the Principle VI
     parity claim.
   - **tasks.md**: widen T028's test scope and add the tasks listed above.
2. Run `/speckit.bugfix.verify` to confirm artifact consistency.
3. Run `/speckit.implement` to apply the code fix in `src/ui/material/terminal_pane.rs`, test-first
   per Constitution Principle I.
