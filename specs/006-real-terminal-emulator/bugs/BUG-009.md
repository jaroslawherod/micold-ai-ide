# Bug Report: the settings contract's example document does not parse — a `settings.json` copied from it loses every setting

**Type**: Spec defect in a contract (the example contradicts the code and the contract it extends;
the code is correct)
**Severity**: Low (no code path writes the example; a person or agent copying it by hand gets a
file the app rejects, moves to `settings.json.bak`, and replaces with the defaults)
**Feature**: `006-real-terminal-emulator` (FR-021; `contracts/settings-schema.md`). Sibling in
`027-sandboxed-daemon-runtime` (`contracts/sandbox-settings-schema.md`). First recorded, and left
uncorrected as another feature's contract, in
[003 BUG-003](../../003-material-design-layout/bugs/BUG-003.md); reproduced on `origin/main` at
`23a0e0ee`
**Reported**: 2026-09-27
**Status**: Patched
**Patched**: 2026-09-27. Phase 16 (T084–T085) added; no requirement changed, no task reopened.

## Description

`contracts/settings-schema.md` shows the on-disk document as:

```jsonc
{
  "settings_version": 2,
  "theme": "FollowSystem",
  "scrollback_lines": 10000
}
```

`ThemePreference` (`crates/micold-core/src/theme.rs`) is `#[serde(rename_all = "snake_case")]`, so
the only accepted values are `"follow_system"`, `"light"` and `"dark"`. The 003 contract this one
extends says exactly that. `"FollowSystem"` is a present field naming no variant, which the 003
compatibility rules make a failed read on purpose: `JsonFileSettingsStore::load` moves the file to
`settings.json.bak` and loads `Settings::default()` with `LoadStatus::Recovered`.

Feature 027's contract repeats the example with `"theme": "System"`, which fails the same way.
Every other field in both examples parses.

**Expected**: every `settings.json` example in a settings contract is a document the app loads as
written (`LoadStatus::Loaded`), with the theme it names.

## Reproduction

`crates/micold-core/tests/settings_contract_examples.rs` extracts each ```` ```json ````/```` ```jsonc ````
settings example from the 003, 006 and 027 settings contracts, strips `//` comments, writes it as
`settings.json` and loads it through `JsonFileSettingsStore`. On `origin/main` `23a0e0ee`:

- 003's example loads as `Loaded` with `follow_system`.
- 006's loads as `Recovered`, and `settings.json.bak` exists.
- 027's loads as `Recovered`, and `settings.json.bak` exists.

To run it against the contracts as they are on `origin/main`, from a clean checkout of a commit
that contains this fix (the last step restores the contracts from `HEAD`, so uncommitted edits to
them would be lost):

```bash
git checkout origin/main -- specs/006-real-terminal-emulator/contracts/settings-schema.md \
  specs/027-sandboxed-daemon-runtime/contracts/sandbox-settings-schema.md
scripts/build-lock.sh cargo test -p micold-core --test settings_contract_examples   # fails: 006 and 027 Recovered
git checkout HEAD -- specs/006-real-terminal-emulator/contracts/settings-schema.md \
  specs/027-sandboxed-daemon-runtime/contracts/sandbox-settings-schema.md
```

Without the test, write either example (with its `//` comments removed) to
`$XDG_DATA_HOME/micold-ai-ide/settings.json` under a private `XDG_DATA_HOME`, and load it with
`JsonFileSettingsStore::at(path).load()`. The status is `Recovered`, `settings.json.bak` holds the
example, and the settings are the defaults.

## Sweep

Every `"theme"` value in `specs/`, `docs/` and `site/`: 003's contract and quickstart, 003 BUG-003,
003's walkthrough evidence, 010 BUG-014 and `site/capture/scenes/lib.sh` all write snake_case. The two
contracts above are the only wrong ones. No other contract shows a whole `settings.json` (011's
addition names fields in prose). Prose that names the Rust variant (`FollowSystem` in 003's
data model and theme contract) refers to the enum, not to the stored value, and is left alone.

This has already happened to someone. The 031 visual pass
(`specs/031-clickable-terminal-links/visual-pass.md`) hand-wrote a `settings.json` with
`"theme": "System"`. It was rejected silently and recovered to the defaults, and it took a temporary
test to find the serde error.

## Root Cause Analysis

The example was written from the enum's Rust variant names (`FollowSystem`, and later a shortened
`System`), not from its serialized form. Nothing reads contract examples, so nothing caught the
difference. The 003 contract states the serialized values correctly, and 006 and 027 extended it
without copying them.

## Recommended Fix

Correct both examples to `"theme": "follow_system"`. Keep the new test as the gate. It reads the
three contracts, so they become test inputs. `.gitattributes` must declare them `-micold-docs`, as it
does for every other spec a test reads, or an edit to an example would skip the suite that checks it.
No code change.
