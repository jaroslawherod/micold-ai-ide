**Type**: Implementation drift
**Severity**: Medium
**Feature**: `010-daemon-session-persistence` (US2, FR-016d) — observed on branch `fix/white-symbol-at-session-name`
**Reported**: 2026-07-27
**Status**: Resolved
**Patched**: 2026-07-27 — `spec.md` gained FR-016e + SC-018; `plan.md` annotated (Principle VIII,
structure entry, Risk 6); `tasks.md` reopened T048 and added Phase 17 (T101–T104). Cross-feature
notes added to `specs/004-material-icons/spec.md` (tofu edge case, Assumptions tail) and its T005
scope note.
**Resolved**: 2026-07-27 — the badge now draws `Icon::ActivityWorking` (`U+E837`
`radio_button_checked`, filled centre) and `Icon::ActivityEnded` (`U+E836`
`radio_button_unchecked`, empty ring) through `crate::ui::icon(..)` in the Material Symbols font;
codepoints pinned in `tests/icons.rs` and `assets/fonts/PROVENANCE.md`; new
`crates/micold-client/tests/ui_glyph_literals.rs` makes a hardcoded UI glyph a build-time failure.
`mise run test` green (104 groups), `cargo clippy -D warnings` and `cargo fmt --check` clean.

**One finding that changed the fix**: the obvious replacements — `circle` (`EF4A`), `lens` (`E3FA`),
`fiber_manual_record` (`E061`) — are *not* filled in this font. The shipped file is a static
instance pinned at **FILL=0**, where all three rasterize as rings. Choosing by icon name would have
swapped a blank box for two indistinguishable rings: still passing every glyph-presence check, still
failing the requirement. `radio_button_checked` is the only same-diameter glyph here with a
genuinely filled centre. Verified by rendering the glyphs out of the shipped `.ttf` at the real badge size
(`sidebar::TAG` = 10px) rather than trusting the names.

**Remaining**: the live-GUI walkthrough (T104) — watching a real session move Working → Awaiting
input → Ended in the sidebar — still needs a human at the app; it is not reproducible headlessly.
The glyph-level property it would confirm is verified deterministically above.

## Description

In the sidebar session list, a blank placeholder rectangle (a missing-glyph box, "tofu") is drawn
between a session's leading status icon and its name. Reported against the session row
`Fetch latest state of repository`, where the row reads:

```
[check_circle icon] [▯ blank box] Fetch latest state of repository        [×]
```

The box is not part of the session name and cannot be selected or removed by the user. It appears on
every session row whose activity signal is anything other than `Unknown`.

## Root Cause Analysis

`ActivityBadge` (`crates/micold-client/src/ui/material/activity_badge.rs:75-88`) renders the
activity dot as **raw Unicode literals in the default text font**, bypassing the shared `Icon`
vocabulary:

```rust
// `●` (U+25CF) filled for live states, `○` (U+25CB) hollow for a spent one.
let (glyph, color) = match emphasis(&badge.signal) {
    Some(BadgeEmphasis::Working)   => ("\u{25CF}", r.primary),
    Some(BadgeEmphasis::Attention) => ("\u{25CF}", r.error),
    Some(BadgeEmphasis::Ended)     => ("\u{25CB}", r.on_surface_variant),
    None => return Space::with_width(Length::Shrink).into(),
};
…
text(glyph).size(badge.size)…
```

`text(..)` draws in `iced::Font::DEFAULT` (`crates/micold-client/src/main.rs:407`), which is iced's
bundled **Fira Sans**. Verified directly against the shipped font files with `ttf-parser`:

| Codepoint | FiraSans-Regular (iced default) | MaterialSymbolsOutlined.ttf (shipped) |
|-----------|--------------------------------|----------------------------------------|
| `U+25CF` ● BLACK CIRCLE  | **no glyph** | no glyph |
| `U+25CB` ○ WHITE CIRCLE  | **no glyph** | no glyph |
| `U+2022` • BULLET        | glyph present | no glyph |
| `U+F0BE` `check_circle`  | no glyph | glyph present |

Neither font maps `U+25CF`/`U+25CB`, so the badge slot resolves to nothing and the renderer emits a
blank box. The `check_circle` immediately to its left renders correctly because it goes through
`Icon::ActiveMarker` → the Material Symbols font.

**Ruled out**: a stray character in the session title. The persisted title is clean — the store at
`~/.local/share/micold-ai-ide/projects/8d4b6897c9929be6.json` holds exactly
`'Fetch latest state of repository'`, no leading glyph and no variation selector. The daemon's
`strip_status_glyph` (`crates/micold-daemon/src/terminal.rs:164`, T047) is working as specified;
the box sits in the badge slot, which `TreeItem` renders between the leading icon and the label
(`crates/micold-client/src/ui/material/tree_view.rs:219-231`).

**Why the existing guard missed it**: `tests/icons_font.rs::every_icon_codepoint_has_a_glyph`
iterates `Icon::ALL` only. `ActivityBadge` never enters that vocabulary — it hardcodes literals — so
it sits entirely outside the build-time tofu guard that feature 004 established. The drift is
between T048's implementation and feature 004's FR-001/FR-002/FR-003 + SC-005, which the
`icons.rs` module doc still claims holds project-wide ("a misspelled or missing icon is a compile
error rather than a runtime blank box (\"tofu\"; FR-003, SC-005)").

**User-visible consequence beyond cosmetics**: FR-016d asks the user to tell activity states apart
"at a glance". All three signalled states now render as the *same* box — filled-vs-hollow shape
encoding is lost entirely, leaving only the tint to distinguish them. The badge under-delivers on
the requirement it exists to satisfy.

## Artifact Traceability

### spec.md — `specs/010-daemon-session-persistence/spec.md`

- **Affected user story**: User Story 2 — "Attach, drive, detach" (P1), line 90.
- **Affected requirements**:
  - **FR-016d** (line 358): "The client MUST display each session's activity signal in the session
    list … so a user attaching after time away can see at a glance which sessions are waiting on
    them." Partially defeated — all signalled states render identically.
  - **FR-016c** (line 356): "Working" MUST be ambient and MUST NOT compete for attention. A tofu box
    is a visual defect that draws attention regardless of state.
- **Gap identified**: The spec does not state that the activity indicator must be drawn from the
  shared icon vocabulary and covered by the font-integrity guard. Nothing in feature 010 forbids a
  new surface from hardcoding a raw codepoint in the default font.

### spec.md — `specs/004-material-icons/spec.md` (cross-feature)

- **Affected requirements**:
  - **FR-001** (line 124): a single shared icon set every surface draws from.
  - **FR-002** (line 126): icons exposed by stable names, "rather than requiring callers to use raw
    glyph codepoints" — directly violated.
  - **FR-003** (line 128): closed name→glyph mapping, unknown names caught at build time.
  - **SC-005** (line 180): "No \"tofu\"/blank-box placeholder ever appears in the running UI
    (0 missing-glyph occurrences at runtime)." Now false in the shipped UI.
  - **Edge case "Missing glyph / tofu"** (line 104): "the system MUST fail closed at build time …
    so a blank box (\"tofu\") can never reach the running UI." The guard is only as wide as
    `Icon::ALL`; a caller that bypasses the enum escapes it.
- **Gap identified**: FR-003's closed-vocabulary guarantee has no enforcement against *new* surfaces
  that skip `Icon` entirely. The invariant is documented but not defended.

### plan.md — `specs/010-daemon-session-persistence/plan.md`

- **Affected sections**:
  - Line 130 — "prompt and activity-indicator affordances … MUST be added as shared primitives".
    The primitive was added, but it does not draw from the shared *icon* primitive.
  - Line 205 — the source layout entry `activity_badge.rs  # NEW shared primitive (builder API)`.
- **Impact**: the plan should record that a shared UI primitive rendering a glyph must source it
  from `Icon`, not from a literal — the constraint that would have prevented this.

### tasks.md — `specs/010-daemon-session-persistence/tasks.md`

- **Affected task**: **T048** (line 183) — `[X] [P] [US2] Build the activity_badge shared primitive
  … render it in the session list for every session (FR-016d)`.
- **False completions**: **T048 is marked `[X]` but its rendered output is a blank box**, so the
  FR-016d display requirement it claims to satisfy is not met on screen. Its "Done" note describes
  filled/hollow dots that never reach the user.
- **Related but correct**: T047 (line 182, OSC-title glyph stripping) is *not* at fault — verified
  above.
- **Missing tasks**:
  1. Add the activity-dot glyphs to the closed `Icon` enum and render the badge through the
     `icon(..)` helper + Material Symbols font. Candidates verified present in the shipped
     `MaterialSymbolsOutlined.ttf`: `circle` `U+EF4A`, `fiber_manual_record` `U+E061`, `lens`
     `U+E3FA` (filled); `radio_button_unchecked` `U+E836` (hollow). Requires the matching
     `assets/fonts/PROVENANCE.md` table rows and `tests/icons.rs` codepoint locks.
  2. Widen the tofu guard so it cannot be bypassed again: a test asserting that no UI source file
     renders a non-ASCII literal through `text(..)`, or that every glyph the client draws comes from
     `Icon::ALL` — the check that would have caught T048 at build time (SC-005, feature 004).
  3. Re-validate the FR-016d at-a-glance distinction: Working / Awaiting input / Ended must be
     distinguishable by **shape**, not tint alone.

### Cross-feature: `specs/004-material-icons/tasks.md`

- **Affected task**: **T005** (line 56) — the `tests/icons_font.rs` integrity test. Scope is
  `Icon::glyph()` only; it cannot see a hardcoded literal.
- **Affected task**: **T028** (line 152) — quickstart validation "that no tofu appears (SC-004,
  SC-005)". That manual check now fails on the sidebar session rows.
