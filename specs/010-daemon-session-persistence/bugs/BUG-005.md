**Type**: Implementation drift
**Severity**: Low (cosmetic + misleading semantics; no functional loss)
**Feature**: `010-daemon-session-persistence` (US2, FR-016d) — icon originates in
`005-worktree-session-terminal`; observed on branch `fix/side-bar-item-name-is-not-waped`
**Reported**: 2026-07-27

pre-fix client did capture the bug as reported — `check_circle` on every session row, one of them

stays **Patched**, not Resolved, until someone expands a worktree in a client running this build.

## Description

Every session row in the sidebar draws a ✓-in-a-circle glyph immediately left of the activity dot
and the session name:

```
[✓ check_circle] [● activity dot] Fetch latest state of repository        [×]
```

The glyph is `Icon::ActiveMarker` (`check_circle`, `U+F0BE` — `assets/fonts/PROVENANCE.md:47`),
applied unconditionally at `crates/micold-client/src/ui/sidebar.rs:489`:

```rust
TreeItem::new(1, session.label.display().to_string(), tint)
    .with_icon(Icon::ActiveMarker)
```

There is no branch on state. A `Failed`, `Idle`, `Running`, `Starting`, `Restarting` and
`InterruptedResumable` session all render the identical checkmark, so the glyph conveys **zero
information per row** while actively suggesting a meaning it does not have: a checkmark next to a
session reads as "done / succeeded / OK", which is wrong for a crashed or interrupted session.

This is the same row documented in [BUG-004](BUG-004.md), where the `check_circle` was noted in
passing as the one glyph that *did* render correctly. This report is about whether it should be
rendering at all.

## Root Cause Analysis

The glyph is a leftover from a different concept. `Icon::ActiveMarker` was specified in feature 004
as the **active known-project marker** — the replacement for the `●` bullet that marked which
project in the list is the current one (`specs/004-material-icons/research.md:105`,
`specs/004-material-icons/tasks.md:40`/`T014`, `contracts/icon-api.md:70` — *"Active known-project
marker (was `●`); marker only; no action"*). Its two legitimate call sites remain
`crates/micold-client/src/ui/shell.rs:163` and
`crates/micold-client/src/ui/material/project_switcher.rs:138`, where "active" is a real, varying
property of the row.

Feature 005 (`6aff29b`, *"worktree & session navigation with embedded terminal"*) built the sidebar
tree and reused the same variant as a generic leading bullet for session rows, where nothing varies.
The name travelled but the semantics did not: on a session row `ActiveMarker` marks nothing.

Two later features then made it redundant rather than merely meaningless:

- **008 (`008-worktree-sidebar-refinement`)** removed the equivalent leading icon from *worktree*
  rows on exactly this reasoning — **FR-010**: *"The system MUST remove the git-status icon
  previously shown next to each worktree"*, closed by **T044** (*"Confirm the leading git icon is
  fully removed"*). The session rows were not in that task's scope, so the sidebar has since been
  half-migrated: worktree rows are icon-free, session rows are not.
- **010 US2** added `ActivityBadge` immediately to its right — a leading indicator that *does* vary
  per session. Two adjacent leading glyphs, one of which is constant, is precisely the clutter
  FR-009/FR-010 were minimising.

## Validation: can the activity badge replace it?

**Yes for meaning; not yet for layout.** Three separate things need to hold, and one does not.

### 1. Information carried by the glyph itself — nothing to replace ✅

The icon is state-independent (see above). Removing it removes no signal.

### 2. Information carried by the glyph's *tint* — survives removal ✅

The row tint is the only state-varying part of the icon today (`sidebar.rs:479-486`):

| `SessionLifecycle` | tint |
|---|---|
| `Failed` | `r.error` |
| `Idle` | `r.on_surface_variant` |
| `InterruptedResumable` | `r.primary` (FR-006a — "visibly different from both running and a deliberately stopped session") |
| `Starting` / `Running` / `Restarting` | `r.on_surface` |

`TreeItem.tint` is applied to *every* part of the row, not just the icon — the twisty
(`tree_view.rs:207`), the icon (`:219`), the **label** (`:234`) and the trailing close button
(`:241`). So lifecycle colour continues to reach the user through the session name itself after the
icon is gone. **No lifecycle information is lost.**

Note this also means the badge does **not** need to absorb the lifecycle states, which is fortunate
— it could not. The two live in different domains and are not interchangeable:

| | `SessionLifecycle` (`micold-core/src/session.rs:65`) | `ActivitySignal` (`protocol/messages.rs:575`) |
|---|---|---|
| source | daemon process supervision | `claude` hooks |
| values | `Idle`, `Starting`, `Running`, `Restarting{attempts}`, `Failed`, `InterruptedResumable` | `Unknown`, `Working`, `AwaitingInput`, `Ended{reason}` |
| answers | "is the process up?" | "does it want me?" |

`ActivityBadge` cannot express `Failed` or `InterruptedResumable`, and must not be asked to — H1/H2
forbid inventing signal. The tint on the label is the correct carrier for lifecycle, and it already
is one.

### 3. Layout: the icon is currently the row's fixed-width leading anchor ⚠️ **blocker**

This is the one real function the glyph performs, and the badge does **not** currently provide it.
`ActivityBadge` returns a zero-width `Space` for `ActivitySignal::Unknown`
(`activity_badge.rs:88`):

```rust
None => return Space::new().width(Length::Shrink).into(),
```

`Unknown` is not a rare state — it is the default for any session whose hooks are unconfigured, and
the state every session occupies before its first signal arrives. Today the constant `check_circle`
keeps all session labels starting at the same x regardless; remove it and the row's leading width
becomes a function of the activity signal. Consequences:

- Hook-less projects: session names sit left of sibling rows that have a badge — a ragged list.
- Signalled projects: the label **shifts horizontally** as a session moves
  `Unknown → Working → Ended`, and back to `Unknown` on reconnect. Rows visibly jump.

The fix is small and belongs with the removal: give the `Unknown` arm a fixed-width `Space` of
`sidebar::TAG` (10.0, the badge's own size) instead of `Length::Shrink`, so the badge slot is
constant-width whether or not it draws. That preserves the alignment the `check_circle` was
incidentally providing while still rendering nothing for `Unknown`, honouring H2. (The same change
also removes an existing minor defect: a `Shrink` spacer between two elements in a
`.spacing(spacing::XS)` row contributes *two* XS gaps instead of one, so `Unknown` rows already
have a slightly wider leading gutter than signalled rows.)

**Conclusion**: the badge can be the session row's sole leading indicator, conditional on the
fixed-width `Unknown` slot. With that in place the removal is information-preserving.

### Scope check

- `Icon::ActiveMarker` **must stay** in the `Icon` enum — `shell.rs:163` and
  `project_switcher.rs:138` are its correct uses. Only the `sidebar.rs:489` call site is obsolete.
- No test asserts the session-row icon. `crates/micold-client/tests/icons.rs:16` locks the
  *codepoint*, which is unaffected; `tests/icons_font.rs` and `tests/ui_glyph_literals.rs` are
  vocabulary/font guards and stay green.
- If a *meaningful* leading icon is wanted on session rows later, `mode_glyph()`
  (`icons.rs:203` → `Icon::AiCli` / `Icon::RegularTerminal`) already maps a real per-session
  property. Out of scope for this fix; noted so the slot is not refilled with another constant.

## Artifact Traceability

### spec.md — `specs/010-daemon-session-persistence/spec.md`

- **Affected user story**: User Story 2 — "Attach, drive, detach" (P1).
- **Affected requirements**:
  - **FR-016d**: the activity signal must be readable "at a glance". A constant checkmark abutting
    the varying dot competes with it and dilutes the glance.
  - **FR-016c**: `Working` must be ambient and must not compete for attention — a permanent
    success-coloured checkmark on every row is exactly such competition.
  - **FR-006a**: `InterruptedResumable` must be "visibly different from both running and a
    deliberately stopped session". A ✓ on all three works against that distinction.
- **Gap identified**: the spec says what the badge must show but never states that it is the session
  row's **sole** leading status indicator, nor that its slot must be constant-width so rows do not
  reflow as signals change.

### spec.md — `specs/008-worktree-sidebar-refinement/spec.md` (cross-feature)

- **Affected requirements**: **FR-009** (minimal padding, compact rows), **FR-010** (remove the
  leading git-status icon from worktree rows), **FR-011** (state conveyed by a lightweight cue that
  does not reintroduce a leading icon).
- **Gap identified**: FR-010 was scoped to worktree rows only. The same rationale applies to session
  rows and was never extended to them, leaving the sidebar inconsistent between its two row types.

### spec.md — `specs/004-material-icons/spec.md` (cross-feature)

- **Affected contract**: `contracts/icon-api.md:70` defines `ActiveMarker` as the *active
  known-project* marker, "marker only; no action". The sidebar use is outside that definition.
- **Gap identified**: nothing prevents a named icon from being reused for a concept unrelated to its
  name. Related to BUG-004's finding that the icon vocabulary's guarantees are documented but not
  defended.

### tasks.md — `specs/010-daemon-session-persistence/tasks.md`

- **Affected task**: **T048** (the `activity_badge` primitive + its rendering in the session list).
  Complete as written, but it added a second leading indicator beside an existing one without
  reconciling the two.
- **False completions**: none. T048's stated scope did not include removing the pre-existing icon.
- **Missing tasks**:
  1. Drop `.with_icon(Icon::ActiveMarker)` from `session_tree_item` (`sidebar.rs:489`); keep the
     variant and its two legitimate call sites.
  2. Make the badge slot constant-width: `Unknown` renders a `Space` of `sidebar::TAG` rather than
     `Length::Shrink` (`activity_badge.rs:88`), so labels stay aligned and rows do not jump as
     signals change.
  3. Assert the invariant: a test that session rows have no leading icon and that the leading offset
     of a row's label is identical across all four `ActivitySignal` variants.
  4. Record in `spec.md` that the activity badge is the session row's sole leading indicator, and
     that lifecycle state is conveyed by the row tint (`sidebar.rs:479-486`), not by a glyph.

### tasks.md — `specs/008-worktree-sidebar-refinement/tasks.md`

- **Affected task**: **T044** — "Confirm the leading git icon is fully removed". Its confirmation
  covered worktree rows only; session rows kept theirs.
