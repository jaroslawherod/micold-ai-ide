# Bug Report: `ActivitySignal::Ended` is unreachable — a stopped session reads *unknown*, never *ended*

**Type**: Requirement not implemented. The state, the wire variant, the icon and the badge branch all
exist and are unit-tested; the one missing piece is the line that *emits* the event
**Severity**: Low-to-medium. Nothing is shown wrongly — a stopped session falls back to `Unknown`,
which draws nothing, so the H1 rule ("no answer beats a wrong answer") is still honoured. But
quickstart S3's third expectation cannot be met, one third of the badge's vocabulary is dead code
outside the showcase, and a stopped session is visually indistinguishable from a live one whose hooks
never fired
**Feature**: `010-daemon-session-persistence` (US2, SC-015/SC-016, quickstart S3). Observed on branch
`docs/cleanup-completed-features`, pinned client+daemon `0.8.0` built 2026-08-20
**Reported**: 2026-08-25
**Status**: Open

## Description

Quickstart S3 asks for three session states side by side in the list, and expects the third to read
*ended*:

> **Expected**: the waiting session reads *awaiting input*, the busy one reads *working* for the
> **entire** run with **zero** spurious flips to awaiting-input, and the stopped one reads *ended*.

Run headlessly on Xvfb `:83` with four sessions and a `claude` shim on `PATH` (so hooks could be
fired by `curl` against the daemon's real loopback receiver, at zero token cost), the first two
expectations hold exactly. The third does not. Session 4 was stopped cleanly —

```
2026-08-25T15:35:41.400104Z  INFO micold_daemon::state: session stopped
    session=42664d7f-4ccc-431f-9d5b-b2f1464b3412 reason="clean exit"
```

— 200 ms after its shim was told to exit 0, and its row went dim, as a stopped session should. But
**no badge is drawn in its slot at all**: the 9×9 patch at the badge's centre is the row background
alone, the same as session 3's, which never received a hook and is correctly `Unknown`.

## Cause

`ActivityEvent::Ended` has no producer in production code. Every `apply`/`note_activity` call site in
the workspace is one of two events:

| call site | event |
|---|---|
| `crates/micold-daemon/src/hooks.rs:254` | `ActivityEvent::Hook(kind)` |
| `crates/micold-daemon/src/state.rs:1108` | `ActivityEvent::SpinnerObserved` |

`ActivityEvent::Ended { reason }` is constructed only inside `activity.rs`'s own unit tests
(`activity.rs:176, 227, 243, 260`) and by the showcase's posed gallery
(`showcase/sections/atoms.rs:210`). Nothing in `state.rs`'s exit handling — neither the clean-exit
path nor `SupervisionAction::Stop` — applies it.

Compounding it, the fallback is `Unknown` rather than a stale signal: `state.rs:840` notes that a
session with no live entry keeps the catalog's values, and the catalog "never carries activity
(H3/A4)". So the moment the live entry is dropped, whatever the session last read is discarded. Even
if `Ended` were applied at exit, it would have to survive that drop to be visible on the row.

Everything downstream is already in place and needs no change:

- `ActivitySignal::Ended { reason }` — `activity.rs:47`, absorbing, tested
- `WireLifecycle`'s sibling `Ended` variant — `protocol/messages.rs:635`
- `Icon::ActivityEnded` — the hollow ring, `icons.rs:85`
- the badge branch — `activity_badge.rs:96`, `on_surface_variant`, unit-tested at `:131`

## Impact

- Quickstart S3's third clause cannot pass, and neither can the part of SC-015/SC-016 that rests on it.
- The hollow-ring badge is reachable only in the showcase, so a visual regression in it would never
  be caught by using the app.
- A user scanning the list cannot tell "this session finished" from "this session never reported" —
  both draw nothing. The first is a fact worth showing; the second is deliberately silent.

## Suggested fix

Apply `ActivityEvent::Ended { reason }` where the daemon already logs `session stopped` and where
`SupervisionAction::{Stop, GiveUp}` are dispatched (`state.rs:1010-1062`), reusing the same `reason`
string it logs — then make the signal outlive the live entry, either by persisting the last activity
onto the catalog summary for stopped sessions or by deriving `Ended` at snapshot time from a
lifecycle that is no longer running.

The second half is the design question worth settling first: **is *ended* an activity signal at all,
or is it a projection of lifecycle?** The FSM treats it as the former (absorbing state, carries a
reason); the persistence rule H3/A4 — "the catalog never carries activity" — assumes the latter.
Deriving it at snapshot time from `SessionLifecycle` would satisfy both without weakening H3, and
would cost one match arm rather than a new persisted field.

## Reproduction

1. Start two sessions; leave both without hooks.
2. Stop one of them (clean exit).
3. Look at the sidebar rows.

**Actual**: neither row draws a badge; the stopped one is distinguishable only by its dimmed label.
**Expected**: the stopped row draws the hollow `on_surface_variant` ring.
