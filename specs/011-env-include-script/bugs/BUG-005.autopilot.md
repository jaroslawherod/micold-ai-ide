- **Input**: "The daemon's per-directory environment-include cache resolves the environment off-lock and then inserts the result, with no in-flight map — so an invalidation that lands between a resolve and its insert is overwritten by the stale value, and two first-time requests for the same directory each run the startup script instead of sharing one run. env_include_vars_for in crates/micold-daemon/src/state.rs is the cache; the invalidation paths are SettingsSet (invalidate_env_include_all) and WorktreeDelete (invalidate_env_include). The gap is pre-existing in feature 011; feature 029's BUG-001 only added a caller, which is why it was declined there and recorded as a follow-up in specs/029-pi-cli-provider/bugs/BUG-001.autopilot.md under "Follow-ups not done", with the reviewer's two findings quoted. The consequence to fix: after a user changes the environment-include settings, an availability answer or a session spawn can still use the environment from before the change; and repeated opens of the start menu can each pay the script's full cost, bounded only by env_include_timeout_secs. The owning spec is feature 011; confirm from its requirements whether cache coherence is specified there at all. Expect a regression test that an invalidation racing a resolve wins, and one that concurrent first asks for one directory run the script once."
