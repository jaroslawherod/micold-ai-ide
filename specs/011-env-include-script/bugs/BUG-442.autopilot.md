- **Input**: "A session's manual restart does not re-source the environment-include script (FR-007(b))" — Feature 011's FR-007 says the environment-include script is re-sourced fresh when **(a)** the user saves a change to the environment-include settings, or **(b)** the user uses a session's manual restart control. The spec's edge cases repeat (b): a manual restart refreshes the shared snapshot, and the restarted session picks up the fresh values. The daemon handles only (a). The per-directory cache is cleared by `set_env_include` (the `SettingsSet` path) and by `invalidate_env_include`, which is called only when a worktree is deleted (`crates/micold-daemon/src/server.rs`). The restart path (`ClientMsg::SessionRestartShell` and the supervisor's restart) never invalidates. A restarted session therefore gets the cached environment from before any change the user made to their rc files. It is not settled whether this is drift or a deliberate choice made when restarts moved into the daemon (feature 010). Either fix the code to invalidate the restarted session's directory, or amend FR-007(b) to match what the daemon does. Found while tracing BUG-005 (#418).
