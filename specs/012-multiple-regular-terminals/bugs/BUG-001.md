## Description

Screenshot of the terminal bottom bar with two Regular Terminal instances open, from left:
`starting…` · release-focus (keyboard) icon · `1  ×` · a filled pill `2  ×` · `+` · mode toggle.

Three defects:

1. **The instance entries do not read as tabs.** Only the *active* entry has a container (the
   filled pill). Every inactive entry renders as bare text plus a loose `×` with no surrounding
   shape, so the row reads as free-floating characters in the status bar rather than a tab strip.
   The user's expectation — and the language the artifacts themselves use — is a tab-like look for
   *every* entry, active and inactive alike.
2. **Wrong intra-tab layout.** Inside a tab the label and the close button sit adjacent
   (`row![label, close].spacing(XS)`), so the label is left-ish and the `×` hangs immediately off
   it. The label should be centred within the tab and the close button pinned to the tab's right
   edge, with the tab holding a stable width so switching active tabs does not reflow the row.
3. **The close `×` is barely visible on the active (highlighted) tab.** The active tab uses
   `ButtonVariant::Filled` → `primary` background with `on_primary` content
   (`crates/micold-client/src/ui/material/style.rs:440-455`), but the nested close control is
   `IconButton::new(Icon::Close, r)`, whose tint defaults to `on_surface`
   (`crates/micold-client/src/ui/material/icon_button.rs:147`). `on_surface` over `primary` is a
   near-tone-on-tone pair, so the `×` almost disappears exactly on the tab the user is most likely
   to close. The tab's own label is fine — plain `Text` inherits the button's `on_primary`; only
   the icon opts out.
4. **The release-focus (keyboard) button is obsolete.** Feature 023 made focus acquisition
   automatic on every navigation and removed the click-outside release, leaving this button as a
   permanently-visible control whose job is covered by `Ctrl+Shift+E` and by simply navigating
   elsewhere. It is currently *always* pushed into the bar and merely disabled when the terminal
   does not hold the keyboard, so it occupies bar space in every state including the one where it
   does nothing.

## Artifact Traceability

### spec.md — 012-multiple-regular-terminals

- **Affected user story**: Story 2 — "See and switch between all open terminal instances" (P1);
  Story 3 — "Close one instance without disturbing the rest" (P2).
- **Affected requirements**:
  - FR-004 — user must be able to see the list of open instances and switch to any one.
  - FR-005 — the switcher is visible only above one instance.
  - FR-011 — user must be able to close an individual instance.
  - SC-004 — a user must be able to tell which instance is active *from this row alone*.
- **Gap identified**: the spec and its FRs are behavioural only. They never state the entries'
  visual form. Nothing requires an inactive entry to carry a container, nothing fixes the
  label/close arrangement within an entry, and nothing constrains the contrast of controls *nested
  inside* a highlighted entry. SC-004 is satisfied by today's build (the active one is clearly
  distinguishable) while the row still looks wrong — so no existing criterion catches this.

### contracts/terminal-instance-switcher-ui.md — 012

- **Affected sections**: "Instance-switcher row" (lines 26–47), "Placement" (lines 5–11).
- **Impact**:
  - Line 31 specifies "one small entry per element of `session.shells`" — "small entry" is the
    under-specification. It needs to say *tab*: every entry, active or not, is a tab-shaped
    container of consistent size; the label is centred; the close control is trailing, at the
    tab's right edge.
  - Lines 34–37 specify the active entry as "visually distinguished (highlight/selected style),
    mirroring `TreeItem::selected`". That is what produced filled-vs-nothing. It needs to become
    a container-vs-container distinction (active fill vs inactive low-emphasis surface/outline),
    not container-vs-bare-text.
  - Lines 39–41 specify the close as "a small trailing icon/button, reusing `Icon::Delete`" —
    silent on tint. It must require the close glyph to take the tab's own on-color, so it stays
    legible on the active tab's fill. (Note: the contract says `Icon::Delete`; the implementation
    uses `Icon::Close` — a separate, cosmetic drift worth reconciling while here.)
  - Line 8 lists the release-focus control as part of the bar's inventory; that list changes if
    the control is removed.

### spec.md — 023-terminal-focus-flow

- **Affected requirements**: **FR-021** — "The existing explicit ways to give and take the
  terminal's keyboard — pressing the pane, the reserved release shortcut, **and the release
  affordance in the pane** — MUST continue to work unchanged."
- **Impact**: this is a direct **spec conflict**. Removing the button, as the report asks, violates
  FR-021 as written. FR-021 must be amended to drop the affordance from the preserved set, leaving

  `crates/micold-client/tests/terminal_bar_stability.rs::bar_does_not_branch_on_focus` still holds

### contracts/focus-model.md — 006-real-terminal-emulator

- **Impact**: this is the original source of the requirement. It must be amended alongside 023

## Root Cause Analysis

**Defects 1–3** are a spec oversight in feature 012. The switcher contract was written in
behavioural terms — what the row lists, what is clickable, what dispatches what — and delegated
appearance to a one-line analogy ("mirroring `TreeItem::selected`"). `TreeItem` is a full-width
list row where a bare-text inactive state reads fine; a horizontal strip of short numeric labels in
a status bar is a different form, and the analogy did not transfer. The close-icon contrast follows
from the same omission compounded by a component default: `IconButton` hardcodes an `on_surface`
tint, which is correct on a surface and wrong inside any filled container — the contract never
constrained a nested control's tint because it never anticipated the nesting mattering.

**Defect 4** is a superseded requirement, not an error. The affordance dates from feature 006, when
focus was acquired only by an explicit click and could be lost by clicking outside; an always-visible
way out was a real safety valve. Feature 023 changed the model underneath it — navigation now
acquires focus automatically, click-outside no longer releases — but 023 deliberately listed the
affordance under "Preserved behaviour" rather than re-examining whether it still earned its place.
It does not: the chord covers the keyboard-only user, and navigation covers everyone else.
