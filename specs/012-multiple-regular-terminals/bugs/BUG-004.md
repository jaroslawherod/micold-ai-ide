# Bug Report: a tab that offers a restart cannot fit one — the button lays out 0dp wide

**Type**: Spec conflict
**Severity**: High
**Feature**: 012-multiple-regular-terminals (`fix/terminal-tabs-indicator` → merged to `main`)
**Reported**: 2026-08-18
**Status**: Patched
**Patched**: 2026-08-18 — Phase 12 (T064–T071); FR-004c amended, FR-010a and SC-010 added,
FR-004a annotated

## Description

An open Regular Terminal instance whose own process has exited shows a **restart** affordance inside
its tab (FR-010, FR-011a). It is not pressable, because it has no width.

`TAB_WIDTH` is 128dp (FR-004c). After the tab button's `spacing::SM` padding the content row is
given **112dp**, and its children ask for:

| child | wants |
|---|---|
| leading spacer (balances the close control) | 48.0 |
| `spacing::XS` | 4.0 |
| label (`"3"`) | 6.8 |
| `spacing::XS` | 4.0 |
| close control | 48.0 |
| `spacing::XS` | 4.0 |
| restart button | 51.5 † |
| **total** | **166.3** |

† The restart button's own want cannot be read from this tab — it was squeezed to 0. 51.5 is the
laid-out width of the **session-level** restart button in the `session-terminal-bottom-bar` covered
state, which is built identically (`Button::with_content` around a `TypeRole::Label` "restart",
`spacing::SM` padding) and is not competing for space. The shortfall is what matters and is exact
regardless: the row was given 112.0 and its first six children alone want 114.8.

iced resolves the 54.3dp shortfall by shrinking the trailing children. Recorded in
`crates/micold-client/tests/fixtures/layout_snapshot.txt`, covered state
`session-terminal-instance-tabs`:

```
@ terminal.tabs.exited          -> 0/0/0/1/1/1/0/3/2      1032.0  748.0  128.0  40.0
                                   …/2/0/0/1/2  (close)   1102.8  759.0   45.2  21.0
@ terminal.tabs.exited.restart  -> 0/0/0/1/1/1/0/3/2/0/0/1/3
                                                          1152.0  759.0    0.0  21.0
```

Two consequences, and the second is not about the restart affordance at all:

1. **FR-010 is unreachable from the tab.** A background instance that exits cannot be restarted
   without first selecting it — and selecting it is precisely what FR-010 says should not be
   necessary ("restarting only that instance", T028: "so a background instance can be restarted
   without first switching to it").
2. **The close control on that tab drops to 45.2dp**, below
   `anatomy::button::MIN_TOUCH_TARGET` (48.0). Feature 018 FR-027/SC-008b state that floor, and
   feature 018's own BUG-002 was filed because that figure had been written and then discarded. It
   is being discarded again here, by a different mechanism — not overwritten, but competed away.

The two tabs without a restart affordance are correct: 128.0 × 40.0 each, active indicator
112.0 × 3.0, inactive tabs reserving a 3.0-high rule they do not draw. FR-004b, FR-004c and SC-008
hold everywhere the restart affordance is absent, which is every state anyone looked at.

## Root Cause Analysis

A constant introduced to fix one geometry defect created another, in a sibling of the child it was
reasoning about.

BUG-002's visual pass found the active tab stretched several times wider than its neighbours: the
indicator is a rule, `Divider` is `Length::Fill`, and inside a content-width tab that `Fill`
resolved against the button's available space. `TAB_WIDTH` fixed it correctly and FR-004c records
why. But the width was chosen from what the *common* tab holds — spacer, label, close — and every
tab anyone looked at during that pass was a common tab. Three states of the switcher were exercised
(inactive, active, activation) and none of them was **exited**, so the one tab with a fourth child
was never drawn.

Why nothing caught it afterwards is the more useful half:

- **No gate could.** The strip was in no covered state at all — `session-terminal-bottom-bar` builds
  a session with no shell instance and `instance_switcher_row` returns `None` below two — which is
  what T063 was filed to fix and how this was found. Registering that state made the defect the
  fixture's first observation.
- **The gates that exist would still not have caught it**, and this matters for the fix. Every node
  is exactly where its own layout says it is: a 0dp button contains its 0dp child, escapes nothing,
  and overflows nothing. `mise run test` is **1914 passed, 0 failed** over a zero-width control.
  The anatomy gates read a component against its declared extent, and a tab's children declare
  none — they are assembled at the call site, which is the same blind spot feature 018's BUG-007
  found for the project-switcher trigger and answered with `gates/sibling_parity.rs`.
- **The source comment says the opposite of the code.** `ui/terminal.rs`, on the restart affordance:
  "It widens its own tab, which SC-008 permits: that is a lifecycle change, not a change of which
  tab is active." That was true before T056 and false after it, in the same file, and no test reads
  comments.

## Recommended Fix

The decision to make first: **does the restart affordance belong in the tab at all?**

- **(a) Size `TAB_WIDTH` to the widest tab the feature can produce.** Smallest change, keeps FR-010
  where FR-011a puts it. Costs every tab the width of a restart button most of them never show —
  at three instances the strip already spans 400dp of a 1014dp bar, and it grows with instance count
  in a bar that also holds a title, a status, two icon buttons and, in AI CLI mode, more.
- **(b) Move the restart out of the tab** into the right-click menu the deferred rename already
  needs (BUG-002 "Related"). Keeps tabs narrow and makes the tab a tab. Costs a hidden affordance
  for a recovery action, and a menu is not discoverable the way a visible button is.
- **(c) Two widths — a restartable tab is wider.** Rejected on sight: it reintroduces exactly the
  reflow SC-008 forbids, since a tab would change width when its instance exits.

**(a) is the recommendation**, with the figure *derived* in the spec rather than chosen, and (b)
filed as the follow-up once a context menu exists for the rename. Whatever is picked, the fix must
carry a gate that fails when a tab's children are squeezed — the class of defect here is "a child
asked for more than it got", which no current gate asks about and which the fixture only pins.
