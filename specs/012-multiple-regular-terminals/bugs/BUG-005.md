# Bug Report: a Regular Terminal instance that exits is still reported alive, so restart is never offered

**Type**: Defect
**Severity**: High
**Feature**: 012-multiple-regular-terminals
**Reported**: 2026-08-19
**Status**: Open
**Found by**: the T073 visual pass of `quickstart.md` §4, which could not complete because the
state §4 is about never arrives

## Description

Type `exit` in a Regular Terminal instance and its shell is gone — the pane shows the exit and no
new prompt. The client goes on describing the instance as **running**, indefinitely: the bottom bar
still says `running`, and the tab's context menu offers **Close** only, never **Restart**.

`ShellLifecycle::Exited` is therefore unreachable in the running application. Every affordance
conditioned on it — FR-010's restart, FR-011a's not-running presentation — is dead code in practice.

## How it presents

Reproduced on Xvfb `:77` + lavapipe, client and daemon built together from
`fix/terminal-tab-restart-width` and pinned outside `target-shared/`. Three instances in one Regular
Terminal session; `exit` typed in instance 1; instance 3 then selected so instance 1 was in the
background.

- Instance 1's pane: `$ exit`, then `exit`, then nothing. The shell is dead.
- The bar: `running`, still, 30+ seconds later, and after a fourth instance was opened to force a
  fresh catalogue push.
- Right-click instance 1's tab: a menu with **Close** and nothing else. `Restart` is conditioned on
  `NotStarted | Exited` (`ui/mod.rs::shell_instance_menu_items`) and the lifecycle is still
  `Running`.
- Pressing **Close** did remove instance 1 and left the active instance alone, so the menu's
  targeting (FR-010a) is correct. It is the *offer* that never appears.

## Root cause

The client cannot see this and is not meant to: "no frames is a quiet shell as much as a dead one"
(`shell/daemon_sync.rs`). It adopts liveness from `SessionSummary::live_shells`, and marks an
instance exited exactly when the daemon stops listing it:

```rust
for instance in existing.shells.iter_mut() {
    if summary.live_shells.contains(&instance.id) {
        instance.lifecycle.mark_running();
    } else if matches!(instance.lifecycle, ShellLifecycle::Running) {
        instance.lifecycle.mark_exited();
    }
}
```

The daemon builds `live_shells` from the live session's process map
(`state.rs::overlay_live_summaries`), filtering it to `SessionProcess::Shell(id)`. Nothing ever
removes a shell process that exited on its own. The only `live.procs.remove(...)` in the daemon is
in `close_shell` — the explicit, user-initiated close. And the supervision tick that *does* notice a
dead process, `supervise_exited_sessions`, reads one key:

```rust
let Some(proc) = live.procs.get(&SessionProcess::Primary) else { continue };
```

So a `SessionProcess::Shell(_)` entry is never checked for liveness and never reaped. `live_shells`
reports it forever, and the client's `else if` branch is unreachable for it.

## Why the suite is green over it

- `micold-daemon/tests/shell_instances.rs` drives `reported_live_shells` through **open** and
  **close_shell**, which is the path that does maintain the map. An instance whose process exits on
  its own is not among the transitions it poses.
- `daemon_sync`'s own tests (BUG-003, T-1880 onward) hand `reconcile_catalog` a summary whose
  `live_shells` already omits the instance, and correctly assert the client marks it exited. They
  test the client's half of a contract whose other half never produces that input.

Two green halves, no whole. This is the same shape as the missing covered state BUG-004 came out of:
each side asserts what it is responsible for and nobody renders the join.

## Expected

An instance whose shell exits is reported as not alive on the next snapshot, the client marks it
`Exited`, the bar says so, and the tab's menu offers **Restart** (FR-008, FR-010).

## Suggested direction

Extend the supervision tick to the shell instances beside the primary: partition
`live.procs` on `pty.is_alive()` rather than looking `Primary` up by key, and drop a dead
`SessionProcess::Shell(id)` from the map so it leaves `live_shells`. Deliberately *not* the primary's
restart policy — a Regular Terminal instance that exits is a user typing `exit`, not a crash to
supervise, and FR-010 puts the restart in the user's hands. The reaping is all that is missing.

A test on the daemon side that poses a shell instance whose process has exited, and asserts it
leaves `live_shells`, is the gate; it fails today.

## Scope

Not `fix/terminal-tab-restart-width`'s doing and not fixed there. That branch moved the restart
affordance from inside the tab to a context menu on it (BUG-004, FR-010b), which is a placement
change; the affordance was equally unreachable before it, for this separate reason. Recorded here so
the two are not confused: BUG-004 is why restart could not be *pressed*, and this is why it is never
*offered*.
