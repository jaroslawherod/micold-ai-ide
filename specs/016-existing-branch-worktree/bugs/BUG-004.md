# Bug Report: A worktree named through a symlink is "not one of this repository's worktrees"

**Type**: Untested flow — an edge case of FR-027/FR-030 and contract `branch-rpc.md` §3a
**Severity**: Low — the app's own client never sends such a path (see *Reach*), so no user flow is
blocked; the daemon's contract is broken for any other caller, and it hung the macOS CI job
**Feature**: 016-existing-branch-worktree (User Story 6, added by BUG-002)
**Reported**: 2026-09-14
**Status**: Fixed — merged in PR #342 (2026-09-14)
**Patched**: 2026-09-14

## Description

`ClientMsg::WorktreeInclude` refuses a worktree the repository does report, when the path it is
given reaches that worktree through a symbolic link:

```
OperationError { kind: NotFound, message: "that is not one of this repository's worktrees",
                 detail: Some("/tmp/.tmpx9PCsf/elsewhere/olx") }
```

`WorktreeExclude` has the mirror defect, silently: given the linked spelling of an included worktree
it answers `OperationOk` and changes nothing, so the worktree stays listed.

The ordinary way to meet it is macOS, where the temporary directory is under `/var`, itself a link
to `/private/var`. Git reports worktree locations canonically, so every path built from
`std::env::temp_dir()` there is a different spelling of what git reports. That is how it was found:
feature 010's PR #330 ran the daemon's tests on macOS for the first time, and
`mutation_semantics.rs`'s include tests were refused there and waited on a reply that never came.
#330 worked around it in the tests by canonicalizing the path they send. This report is for the
daemon.

## Reproduction

On `origin/main` at `226d3a8b`, on Linux, no macOS needed:

1. A repository, and a worktree added outside it at `<real>/olx` (`git worktree add`).
2. A symlink `<links>/elsewhere` → `<real>`.
3. Send `WorktreeInclude { project, path: <links>/elsewhere/olx }`.

Automated as
`crates/micold-daemon/tests/mutation_semantics.rs::a_worktree_named_through_a_symlink_is_included_and_excluded_as_itself`,
which fails with the `OperationError` above.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 6 — Include a worktree that already exists (P6)
- **Affected requirements**:
  - **FR-027**: the offer to include a worktree the app does not manage. It is refused when the
    worktree is named by another spelling of its location.
  - **FR-030**: inclusion is reversible. Stopping by another spelling does nothing, silently.
- **Gap identified**: no requirement says what identifies a worktree's *location*. The spec speaks
  of "its location" throughout US6 and never says that two paths reaching the same directory name
  the same location, so the literal comparison was never wrong against a stated rule.

### plan.md
- **Affected sections**: the BUG-002 amendment on the persisted included set (the one persisted
  value, Principle IV). It records *that* paths are stored, not *which spelling*.
- **Impact**: say the stored path is the location as git reports it, whatever spelling was asked
  for, so `reconcile()`'s exact match against git's records stays correct by construction.

### data-model.md
- **Included worktrees**: "Paths are **absolute and canonical**, the same normalization projects
  themselves use, so a path recorded once matches the record git reports for it." The normalization
  projects use is `canonicalize_best_effort`, which is lexical and deliberately does not resolve
  links, so the second half does not follow from the first. The handler kept the stored set equal
  to git's spelling only by refusing every other spelling.

### contracts/branch-rpc.md
- **§3a**: "The daemon MUST reject a `path` the repository does not report as a worktree." A linked
  spelling *is* a worktree the repository reports; the contract needs to say the check is by
  location, and what the reply's `worktree.path` is.

### tasks.md
- **Affected tasks**: T078 (idempotence and the not-a-worktree refusal), T086 (the daemon handlers:
  "validate the path against the repository's own records").
- **False completions**: none. T086 validates against the records exactly as written; the rule for
  what "matches" was never specified, so neither task is reopened.
- **Missing tasks**: a regression test for both directions through a link, and the fix — added as
  Phase 11, T093–T096.

## Root Cause Analysis

Two literal `PathBuf` comparisons against paths git canonicalized:

1. **Include** — `crates/micold-daemon/src/server.rs`, the `ClientMsg::WorktreeInclude` arm:
   `parse_worktrees(&porcelain).into_iter().any(|rec| rec.path == probe)`. `git worktree list
   --porcelain` prints the real path; `probe` is the caller's spelling. When the check passed, the
   caller's spelling was also what `include_worktree` persisted, so the check was the only thing
   keeping a non-canonical path out of the store — where `reconcile()`'s
   `included.contains(&rec.path)` would not have matched it either.
2. **Exclude** — `crates/micold-daemon/src/catalog.rs`, `Catalog::exclude_worktree`:
   `entry.retain(|p| p != path)`. Idempotence (an unknown path is `Ok` and writes nothing) is what
   makes the miss silent.

An implementation gap under a spec silence, not drift: the code does what T086 says, and the
stored set does match git's records, which is what data-model.md asks. It gets there by refusing.

### Reach

The client never sends a linked spelling. `on_worktree_include_requested` in
`crates/micold-client/src/shell/daemon_sync.rs` sends the holder's path from the branch
explanation, which comes from git's own records, and "Stop showing" sends the row's path, which
came from the daemon. Any other caller of the protocol — and every test that builds a path from the
temp dir on macOS — meets it.

## Recommended Fix

The rule already exists: `same_path()` in `crates/micold-core/src/git.rs` — "whether two paths
name the same location, resolving symlinks when both sides exist", falling back to a literal
comparison when either side is gone — written for this very mismatch (git's resolved path against
the app's own spelling) when deleting a worktree. It is private to that module.

1. Make `same_path()` public and use it for both handlers, rather than writing the rule twice.
2. Include: accept the record `same_path()` matches, and persist and answer with **the record's**
   path, so everything downstream still compares git's spelling with git's spelling.
3. Exclude: remove the stored entries `same_path()` matches, resolving them off the daemon's state
   lock as include already does. Its literal fallback keeps an included
   worktree that has since been removed from disk (FR-031) stoppable by the path its row shows.
4. `/speckit-bugfix-patch`, `/speckit-bugfix-verify`, then the regression test red → green.
