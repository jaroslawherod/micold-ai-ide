# Bug Report: dismissing the overflow menu plays an exit on the project switcher's panel — a surface nobody opened, closing

**Type**: Implementation drift over a spec gap — the overlay primitive lets a surface occupy a
different number of layers depending on whether it is open, and nothing states that it must not.
**Severity**: High — visible on every dismissal of the application's primary menu, on every screen,
and it shows the user a panel they did not open.
**Feature**: `017-material-component-architecture` (FR-008, the one overlay primitive; FR-011, a
component owns its own presentation state). Surfaced by
[`018`'s BUG-007](../../018-material3-visual-system/bugs/BUG-007.md), which gave the project
switcher the shared `MenuOverlay` and with it a fade.
**Reported**: 2026-08-08, from the owner: "after open a menu from application toolbar and clicking
elsewhere to close it. Menu disappears then project switcher menu appears and also disappears."
**Status**: Fixed
**Fixed**: 2026-08-08 on `fix/overlay-layer-identity`, behind a failing test
(`tests/overlay_layer_identity.rs`).

## Description

Open the app bar's ⋮ menu, then click outside it. The menu fades out as it should — and then the
**project switcher's** panel appears where it would open and fades out too, having never been
opened.

## Root cause

A `Surface` contributed a **variable number of layers**: one when it had no backdrop, two when it
did. It has a backdrop only when it is dismissible, which in practice means only while it is open —
`MenuOverlay` deliberately withholds `on_dismiss` while closed, so that a shut menu does not swallow
the next click.

`Overlay::from` therefore built a stack whose child indices depended on which surfaces were open:

| state | stack children |
|---|---|
| nothing open | base, **menu panel (1)**, **switcher panel (2)** |
| ⋮ menu open | base, menu backdrop (1), **menu panel (2)**, **switcher panel (3)** |

`iced::widget::stack` keeps per-child widget state **by index**. Closing the menu removed the
backdrop, shifting every layer above it down one — so the switcher's panel landed on the index the
menu's panel had just vacated, and inherited its widget state. Feature 018 gave that panel its own
fade (FR-011: a component owns its presentation state), so what the switcher's panel inherited was a
transition already in flight. It drew itself at the menu's opacity and played the menu's exit.

**Evidence, from the committed fixture rather than from instrumentation** —
`crates/micold-client/tests/fixtures/layout_snapshot.txt`, same node in two states:

```
main-shell-sidebar-expanded   base 0/2/0  1032,65  240 × 112   the switcher's panel, child 2
toolbar-overflow-menu-open    base 0/3/0  1032,65  240 × 112   the same panel, child 3
```

Nothing about the switcher changed between those two states. Only the menu's openness did.

## Why nothing caught it

- `overlay_stacking.rs` pins the **order** surfaces appear in, which is unaffected — the switcher is
  still above the menu, at both indices.
- `overlay_transition_identity.rs` pins that a *dialog* keeps its identity while it animates out.
  It is about `ClosingOverlay`, a state-level snapshot, not about widget-tree position.
- `component_state_isolation.rs` asserts two instances of a component do not share state. These are
  two instances that did not share state so much as **swap** it.
- The geometry fixture recorded the index change faithfully in both states and had no reason to
  object: each state is internally correct. The defect is in the *relationship between* two states,
  which no snapshot of either can see.

## The fix

A surface is **always** two layers. `Surface::backdrop` returns an element unconditionally; when
there is nothing to catch it is a bare `Space` — no press handler, so it takes no input, and
`Length::Fill` so the stack sizes identically either way. Indices then depend only on how many
surfaces `ui::view` pushes, which is a constant.

## Recommended follow-up

FR-008 should say it, not merely imply it: *the number of layers a surface occupies must not depend
on its own state*, because the widget layer identifies per-child state positionally. That is the
durable statement of what went wrong, and it is one sentence.
