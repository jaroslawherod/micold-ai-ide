# Bug Report: on the neutral `surface_variant` host, the outlined and text buttons fall just under AA once a state layer is composited — and the dark scheme's `outline` border is under 3:1 at rest

**Type**: Untested flow — §1.3 enumerates `primary` on `surface_variant` as a permitted pair and
`tokens_contrast` asserts it, but both read the *resting* colours. A hover or press draws a state
layer over the host, which moves the background toward the label and lowers the ratio the enumerated
pair was measured at. No gate reads the composited value on a neutral host.

**Severity**: Low — every miss is marginal (4.40–4.49:1 against 4.5, 2.42–2.96:1 against 3), the
resting states pass in both schemes, and the affected control is readable in practice. It is a
conformance gap, not a legibility failure of BUG-009's kind.

**Feature**: `018-material3-visual-system` (§1.3 the contrast obligation table, §7.3 buttons and
their state layers, FR-004/FR-005, SC-008).

**Reported**: 2026-08-21

**Status**: Open

## Description

Found while building BUG-009's composition gate
(`crates/micold-client/src/ui/material/composition_contrast.rs`, T151). Run unscoped — over every
notification host rather than only the accent ones FR-004a governs — the walk reports nine
violations that have nothing to do with BUG-009:

| Scheme | Host | Variant | State | Measured | Threshold |
|---|---|---|---|---|---|
| Light | `Info` (`surface_variant`) | Outlined | hovered | label 4.49:1 | 4.5 |
| Light | `Info` | Outlined | pressed | label 4.40:1 | 4.5 |
| Light | `Info` | Text | hovered | label 4.49:1 | 4.5 |
| Light | `Info` | Text | pressed | label 4.40:1 | 4.5 |
| Dark | `Info` | Outlined | active | 1px border 2.96:1 | 3 |
| Dark | `Info` | Outlined | hovered | 1px border 2.51:1 | 3 |
| Dark | `Info` | Outlined | pressed | label 4.48:1 | 4.5 |
| Dark | `Info` | Outlined | pressed | 1px border 2.42:1 | 3 |
| Dark | `Info` | Text | pressed | label 4.48:1 | 4.5 |

Two distinct causes:

1. **The state layer erodes an already-marginal pair.** `primary` on `surface_variant` rests just
   over 4.5:1. The hover and press layers are `primary` at 8% and 12% over the host, which pulls the
   background toward the label and takes the pair under the line. The pair §1.3 blesses is the
   resting one; the state layer is drawn by §7.3 and neither table sees the other.
2. **`outline` on `surface_variant` is under 3:1 in the dark scheme at rest** — 2.96:1, before any
   state layer. That is a straight enumerated-pair miss for a non-text element, independent of any
   composition.

## Artifact Traceability

### spec.md

- **Affected user story**: US4 (a legible, consistent visual system).
- **Affected requirements**: FR-004 (contrast obligations), FR-005 (state layers). SC-008 asserts the

- **Gap identified**: no requirement states the ratio survives a state layer, so the enumerated pair
  is asserted at rest and never at the value the user sees under the pointer.

### tasks.md

- **Affected tasks**: T151 (the composition gate) scopes itself to accent hosts and records this

## Root Cause Analysis

Both tables are individually right. §1.3 enumerates pairs and `tokens_contrast` proves them; §7.3
specifies state layers and `style_states` proves those. The ratio a user actually reads is a function
of both, and nothing multiplies them together on a neutral host. BUG-009 is the same absence at a
much larger amplitude — there the composed pair was 1.00:1 rather than 4.49:1, which is why it was
visible to the eye and this is not.

## Recommended Fix

Not attempted here; BUG-009's fix is scoped to accent fills and this would widen it past its cause.
When taken up:

1. Decide the rule first: either the enumerated pair must clear AA *with the heaviest state layer
   composited* (which re-tunes `primary`'s tone against `surface_variant`), or state layers on
   neutral hosts are declared exempt and the exemption is written down. Guessing between the two in
   code is what produced two tables that cannot see each other.
2. `outline` on `surface_variant` in the dark scheme is a plain 2.96:1 miss and wants fixing either
   way — it needs no state layer to fail.
3. Then widen `composition_contrast.rs` to drop its accent-host filter, which is written as a single
   `imposed().is_none()` skip precisely so it can be removed in one edit.
