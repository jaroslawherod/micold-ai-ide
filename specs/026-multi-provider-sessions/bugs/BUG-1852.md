# Bug Report: Startup keeps a Named/Derived session whose conversation is gone

**Type**: Decision change (follow-up to BUG-1795 D3), not new behaviour: FR-008a already intends that no listed session is neither running nor startable
**Severity**: Low
**Feature**: 026 — multi-provider AI CLI sessions (owner of FR-008a); also supersedes 029 FR-008 and 032 data-model invariant 4 (see *Pending approval*)
**Reported**: 2026-11-14 (issue #1852; follow-up to #1795, fixed in #1835)
**Status**: **Patched**, awaiting approval of the 029/032 clauses; fix tasks T099–T103. **The branch must not merge before T100 and T102 land**: the guide and FR-008a already promise startup removal
**Related**: [BUG-1795](./BUG-1795.md) (D3), #1794

## Description

#1835 removes a session whose conversation is gone at start time and after a crash restart, and by
decision D3 removes nothing at startup. A `Named` or `Derived` session whose conversation is gone
therefore survives a restart as a not-running row that cannot be started until the user tries it.
The open decision (issue body) is to remove it at startup too.

## Reproduction (on `origin/main` fdb923d04, by code, daemon level)

1. A catalog holds a `Named` (or `Derived`) AI-CLI session of an app-assigned-id provider (Claude,
   Copilot) whose conversation file is absent from the provider's store.
2. Start the daemon: `server.rs` (~line 286) runs `present_interrupted_resumable_at_startup`, which
   marks only sessions with a recorded conversation `InterruptedResumable`; this one stays `Idle`.
3. Nothing prunes it: `Catalog::prunable_session_cwds` (`catalog.rs` ~1861) is `Pending`-only, and
   `prune_empty_sessions` runs only for an attached project, off that candidate set.
4. The row stays listed, `Idle`, and its first start is refused by `start_session_gated`
   (`conversation_gone`, `state.rs` ~6814), which now removes it (BUG-1795 T094). Until then it is
   the dead reference of #1795. Pinned by T092(b) of BUG-1795, which asserts it stays listed.

## Root cause

D3 (BUG-1795 ledger, `bugs/BUG-1795.autopilot.md`): startup deliberately removes nothing, because
`prunable_session_cwds` stays `Pending`-only (029 FR-008 / 032 invariant 4). No startup path asks
`DaemonState::conversation_gone` about a `Named`/`Derived` session. A decision, not a defect in code.

## Owning spec

026 FR-008a (startup clause written by BUG-1795). Requirement text already intends the outcome ("every
listed session is running, startable, or removed"); only the exception for named sessions changes.

## Patch

- 026 `spec.md` FR-008a: startup removes a `Named`/`Derived` session whose conversation is confirmed
  gone; ignorance (unresolvable config dir), Pi (self-minted ids), `Pending` and live sessions are
  not removed. Applied.
- 026 `tasks.md`: T099–T103. T093/T098 stay dropped as written.
- `docs/user-guide/worktrees-and-sessions.md` (~line 1381). Applied.
- `BUG-1795.md`: D3 marked superseded.
- Fix (T100): `remove_gone_sessions_at_startup` reuses `conversation_gone` and `remove_dead_session`;
  no new wire message, no persistence format change, no protocol bump.

## False completions

None. T093/T098 were dropped on purpose (D3). T092(b) asserts the old contract and is turned around by T099.

## Evidence / risks for the fix

- Same predicate as start time, so the two cannot disagree: unresolvable config dir is not gone;
  Pi is not covered (`ConversationIdentity::AppAssigned` only).
- Destructive and persisted (archive + durable marker, FR-015), so a lost store must not look like
  lost conversations. `conversation_gone` alone only needs a resolvable config dir. T100 therefore
  also requires the provider's transcript root (Claude: `<config>/projects/`) to exist, read as a directory and be non-empty (unmounted disk, moved home: ignorance,
  remove nothing), and removes nothing for a provider whose every candidate (more than one) is gone at
  once. T099 has a keep case for each.
- Runs before the accept loop, so no client observes the intermediate list.

## Pending approval

The user has not approved changing these clauses. They are NOT edited in this PR; the orchestrator
applies them once approved (T102).

**029 `spec.md` FR-008**, replace

> The application MUST keep a remembered name after the AI CLI's own records for that conversation
> become unavailable or are removed.

with

> The application MUST keep a remembered name while it cannot tell that the AI CLI's conversation is
> gone: the records are unreadable, the provider's store cannot be located or read, or the provider
> assigns its own ids. A conversation is gone only when the provider's store is readable and has no
> record of it. A session whose conversation is found gone, at startup, at start, or on a crash
> restart, is removed, and its name with it (026 FR-008a, BUG-1795 T094, BUG-1852).

**032 `data-model.md` invariant 4**, replace

> 4. A `Derived` session is never pruned by `prunable_session_cwds` (it has, or had, a conversation).

with

> 4. A `Derived` session is never pruned by `prunable_session_cwds` (it has, or had, a conversation;
>    the candidates stay `Pending`-only). A `Derived` session whose conversation is found gone (store
>    readable, no record) is removed by the separate pass of 026 FR-008a (BUG-1852), not by pruning.

Clauses that follow from these two, to be applied with them (each says a deleted conversation leaves
the row or its name in place). Those marked "stays valid" remain true only as "pruning does not
remove it":

- 029 `spec.md` Edge Cases, first bullet: append "...while it cannot tell the conversation is gone; one found gone removes the session (026 FR-008a)."
- 029 `quickstart.md` line 33 (a `Named` session whose transcript was deleted keeps its name, FR-008/C15/US3): reword to "keeps its name through the recovery pass (a `Named` session is skipped); it is removed at startup, with its name, when its conversation is found gone (026 FR-008a)".
- 029 `contracts/session-name-persistence.md` C15 ("what protects FR-008"), `data-model.md` line ~64, and `tasks.md` T028 (line ~218, `prunable_session_cwds` excludes `Named`): stay valid, as "pruning and recovery never remove a Named session".
- 029 `data-model.md` lines ~31, ~94 and the transition `Named(s) -- transcript deleted --> Named(s)` (~120): the transition is "Named(s) -- found gone at startup, start or crash restart --> removed (026 FR-008a)"; a deleted transcript with the store unreadable stays `Named(s)`.
- 029 `research.md` R5: its "kept while refusing to resume" pair is already broken by BUG-1795 (a refused resume removes the session); restate R5 as "the recovery pass never clears a name; removal of a gone session is 026 FR-008a".
- 032 `spec.md` ~line 190 edge case "records are deleted after a label was shown", `research.md` ~192, `tasks.md` T027 note: the label stays only while the session is listed; the session is removed when its conversation is found gone.

## Accepted

A `Named` label can come from the terminal title, so a never-used `Named` session with no transcript
is removed at startup: an unused Named session is removed like an empty one.
