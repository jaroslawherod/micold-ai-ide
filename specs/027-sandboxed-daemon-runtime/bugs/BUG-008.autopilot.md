## Follow-ups not done

- The other credential opt-ins have the absent-item problem the sign-in had before BUG-006's F2.
  `CredentialLayout::conventional` names `~/.gitconfig` and `~/.git-credentials` whether or not
  they exist, and `mount_args` passes them with `-v`, which makes Docker create a missing source as a
  root-owned **directory** in the user's real home. An unset `SSH_AUTH_SOCK` drops the SSH agent
  share with no report at all. Needs its own bug record.
- "Restart the sandbox" (from `Stale` or `Running`) goes back through `bring_up`, and `adopt` attaches
  to the same container whenever its image and fingerprint match, so a restart never picks up a
  changed mount set (projects, credential opt-ins). Seen while designing BUG-008's remedy text; not
  verified at runtime. Needs its own bug record.
- A stopped container adopted with `Start(id)` keeps its bind mounts; if the sign-in token was removed
  from the host since, the runtime recreates the missing source as a root-owned directory — the F2
  hazard from BUG-006, on the adopt path. Not verified at runtime.
- Saving a changed credential opt-in (or project set) does not mark the running sandbox `Stale`, and
  `sandbox_boot.profile` is rebuilt only on a placement change, so a share ticked mid-session applies
  to no container until the placement is moved. FR-004g now reports the sign-in case; the general
  gap needs its own bug record (review A, finding 1).
