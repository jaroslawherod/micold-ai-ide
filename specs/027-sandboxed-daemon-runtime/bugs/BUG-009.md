# Bug Report: A container host receives no GitHub token, so `gh` in the sandbox cannot authenticate

**Type**: Missing requirement (the spec says a sandbox pushes with a stored token; the delivery
never carried one)
**Severity**: High — every session on a container host has no working `gh` and cannot push
**Feature**: 027-sandboxed-daemon-runtime (branch `claude/project-thread-3ppj2n`)
**Reported**: 2026-11-17 (no GitHub issue; filed through speckit)
**Status**: Patched
**Patched**: 2026-11-17

## Description

Settings > GitHub shows two scoped tokens (`max-speed/*`, `jaroslawherod/micold-ai-ide`) and states
that stored tokens let sandboxed sessions push. In the container, `gh` fails: the `gh` shim
(`crates/micold-daemon/src/gh_shim.rs`: `micold-daemon gh-token --cwd $PWD`) finds no token and
exits 1, and `gh` falls back to a stale `~/.config/gh/hosts.yml`.

### Reproduction

On the reporter's container host, `/run/micold/config/daemon.toml` has no `github` section at all.
On `origin/main` (`445f38a8`): `deliver_container`
(`crates/micold-client/src/daemon_config_delivery.rs`) builds `DaemonSettings` with
`github_tokens` empty and copies only the SSH, signing, CA and session files and the git config into
`delivery.secrets`; its callers (`shell/sandbox.rs`) pass it no tokens. Pods do deliver them
(#1760: `select_tokens`, `PodGithubTokens::read`, `pod_github_tokens` in `daemon.rs`).

### Why nothing caught it

The user guide ("Tokens are not special to sandboxes: a host or SSH daemon chooses the token … from
its configuration file") described the daemon's side only; no test rendered a container's file with
a token, because `deliver_container` had no way to be given one.

## Root Cause Analysis

#1527 moved the container's configuration into `daemon.toml` and #1760 later taught pods to receive
tokens, but the container path was never extended: `deliver_container` has no token input and its
callers hold no repositories to select by.

## Decisions

- **D1 — no opt-in switch** (the user's decision): a container host receives the tokens that match
  its projects' repositories plus the unfiltered ones, as `select_tokens` does.
- **D2 — shared code**: `PodGithubTokens::read_at` reads the files for both; `stored_tokens_for`
  selects for both. The container names its copies at `/run/micold/secrets/github-token-<name>`
  and prunes copies no longer selected; the `host` field is kept.
- **D3 — repositories**: those of the container daemon's saved projects (`ProjectsDial::of`), part
  of the bring-up's identity so saving a project re-delivers.
- **AI CLI sign-in** (checked): the Claude token reaches a container by a read-only bind mount of
  the credentials file (FR-004/FR-034 share), not through `daemon.toml`; it is not this gap.
