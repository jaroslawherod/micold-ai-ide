## Follow-ups not done

- An adopted container that mounts an SSH agent socket at a path other than this client's
  current `SSH_AUTH_SOCK` (another login's socket) still counts that mount as a project, so the
  notice stays on until a restart. `container_projects` subtracts only the credential paths the
  layout names (review A round 2, MINOR). Needs a mount-type or source check, or its own issue.
- "Restart the sandbox" goes back through `bring_up`, and `adopt` attaches to the same container
  whenever image and fingerprint match, so a restart never applies a changed mount set (already
  recorded as a BUG-008 follow-up in `bugs/BUG-008.autopilot.md`). After this fix the notice stays
  honest after such a restart (it is measured against the container), but its remedy "Restart it to
  apply" does not work. Needs its own issue.
- Which event set `Stale` in feature 039's C3 pass is not established: the two clients' boot plans
  and bring-up outcomes were not logged. The client could log the adoption decision and the plan's
  project count at `Started`.
