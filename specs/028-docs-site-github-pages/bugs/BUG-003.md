# Bug Report: The site's own transitions move on mdBook's timings, not the application's

**Type**: Implementation drift, which the check for SC-014 cannot see because it only reads
`site.css` (untested flow).
**Severity**: Low. The sidebar and the page wrapper slide over 300 ms `ease`, and several controls
fade colour over 500 ms `ease`. Nothing breaks, and readers who ask for reduced motion get no
transitions at all (FR-030b holds). The site simply does not move the way the application does,
which FR-030a requires.
**Feature**: 028-docs-site-github-pages (FR-030, FR-030a, SC-014)
**Reported**: 2026-09-16
**Status**: Open

## Description

The quickstart Part B pass (B4) probed computed styles on *Worktrees & sessions* while checking
reduced motion: [evidence/quickstart-b.md](../evidence/quickstart-b.md), finding 3. Without
reduced motion, these elements transition on values that are not motion tokens:

| Element | Property | Transition |
|---|---|---|
| `#mdbook-sidebar` | `transform` | `0.3s ease` |
| `#mdbook-page-wrapper` | `margin-left`, `transform` | `0.3s ease` |
| `.chapter-fold-toggle div` (a navigation section's expand arrow) | `transform` | `0.5s ease` |
| `.nav-chapters` (previous/next) | `color`, `background-color` | `0.5s ease` |
| header icons (`.fa-svg`) | `color` | `0.5s ease` |
| `#mdbook-searchbar` | `box-shadow` | `0.3s ease-in-out` |

Only the rules `site/theme/css/site.css` writes itself use the tokens: the app bar's `box-shadow`
(`--micold-motion-duration-short-4`) and the header buttons' `background-color`
(`--micold-motion-duration-short-2`), both on `--micold-motion-easing-standard`. The sidebar slide
is the transition FR-030a names outright ("an expanding navigation section").

## Artifact Traceability

- **Affected user story**: none directly. This is the *Appearance* requirements group.
- **Affected requirements**:
  - **FR-030a**: "The site's own transitions — hover, focus, an expanding navigation section,
    switching theme — MUST use the application's motion durations and easing".
  - **FR-030**: motion values "MUST be derived from the application's own design tokens, not
    restated by hand in a stylesheet".
  - **SC-014**, as enforced: literal durations are forbidden.
- **Gap identified**: none in the requirement. It is explicit, and the implementation does not meet
  it.

### contracts/theme-variables.md

- **Affected**: "transitions use `--micold-motion-*`, and are removed under
  `prefers-reduced-motion: reduce`"; and **Forbidden**: "any literal … duration in `site.css` —

  `site.css` and never overrides for these elements. The grep passes because the literals are in
  files it does not read.

## Root Cause Analysis

The theme replaces mdBook's look by adding `site.css` on top of mdBook's stylesheets, not by
replacing them. Colour, type and shape were overridden wherever mdBook set them, because those
differences are visible in a still screenshot. Transitions are visible only while something moves,
so mdBook's were left as they were. The guard for SC-014 greps `site.css` alone, so it proves that
the site's own file has no literals, not that the page has none. The reduced-motion rule
(`transition: none !important` on `*`) hides the problem from anyone who asks for less motion,
which is also why the automated "nothing moves" check (T074) could not see it.
