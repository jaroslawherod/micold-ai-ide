## Follow-ups not done

- **`claude`'s own resolver order is `agentName || customTitle || aiTitle || summary || firstPrompt`**
  (review A read it out of the decompiled `claude` 2.1.283 bundle). C16.1 ranks `custom-title` above
  `agent-name` instead. The two agree on every transcript observed here, but they would diverge on the
  paths review A names that write `agent-name` without a matching `custom-title` — a "collision"
  rename in the live-name yield handler, and an `n=="auto"` title after a user rename. If that is
  ever observed, it is a new bug against C16.1, not this one. This is first-hand evidence about the
  dependency's format that BUG-002 did not have, and it is the strongest argument for revisiting D4.
- **An empty `customTitle` may be `claude`'s *clear* signal.** Its own reader takes the last
  `custom-title` line including empties and treats an empty value as "no title", deleting the
  sidecar; C16.1/C17 instead skip empties, so a cleared rename would stay pinned and mask the current
  `ai-title`. Unproven reachable (`/rename` rejects an empty name), and honouring it is new behaviour
  → a Phase 1 change, not a bug fix.
- **`read_title` reads the whole transcript** (`read_to_string`); the real BUG-002 transcript is
  32 MB and discovery calls it once per unrecorded session on the blocking hop. Pre-existing, and a
  bounded tail read would change C16/C18's cost contract.
- **The name records carry a `sessionId` that `parse_title` ignores.** Harmless today — the file is
  already per-conversation — but a mirrored foreign record would name a row after another
  conversation. 0 instances in 100+ local transcripts.
- `CopilotProvider` and `PiProvider` are untouched: neither CLI has a rename record of its own in
  the formats read on 2026-09-19 (029-pi-cli-provider R5; 032 *Copilot evidence*). If a later version
  gains one, it is a new bug, not this one.
