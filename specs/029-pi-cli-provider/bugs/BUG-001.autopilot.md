## Follow-ups not done

- The environment-include cache (`env_include_vars_for`, `crates/micold-daemon/src/state.rs`,
  feature 011) resolves off-lock and then inserts, with no in-flight map. An invalidation that lands
  between a resolve and its insert is overwritten, and concurrent first-time asks for the same
  directory each run the script. Both are pre-existing; BUG-001 only adds a caller. Found by M1
  review A.
- The start affordance's chevron and its primary press read one global availability set, which after
  a reconnect or a Settings open holds the home directory's answer. A CLI that only a project-local
  environment-include script puts on `PATH` can therefore stay unreachable in that project. Beyond
  FR-003b as written; see *Declined review findings*. Found by M1 review A.
- Quickstart §B was not re-run at a display for BUG-001, so nothing records the Settings select and
  the override list *drawing* the Pi entry the service now sends. The wiring either side is covered
  by client tests and the change touches neither control's construction. See `evidence/bug-001.md`.
- T069: how `/tmp/does-not-exist.sh` reached a real `settings.json` — separate defect, prior
  evidence `specs/010-daemon-session-persistence/bugs/BUG-025.md`, likely writer
  `crates/micold-client/src/main_tests.rs:1587`.
- The reporter's real `settings.json` holds `env_include_enabled: false` with a
