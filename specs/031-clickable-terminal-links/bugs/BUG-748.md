# Bug Report: Terminal links show no hand cursor on Ctrl/Cmd+hover under a mouse-reporting program

**Type**: Spec gap (the specified rule is the one the reporter experiences as the bug)
**Severity**: Low
**Feature**: 031-clickable-terminal-links (FR-007, FR-016)
**Reported**: 2026-10-10 (issue #748)
**Status**: **Patched** — spec amended 2026-10-13; fix tasks T091–T093 (Phase 9).
**Found by**: user report; reproduced as a rule, not as a defect, over three earlier units
(real-app Wayland runs on sway and Mutter 50.5, whole-window tests in
`crates/micold-client/tests/terminal_link_hand_cursor.rs`, PR #755 and this PR).

## Description

The reporter holds Ctrl over a terminal link and the pointer stays the text I-beam. They run Claude
Code in the pane, which turns on mouse reporting. In a plain shell the same gesture shows the hand.

## Reproduction

1. Open a session whose program has mouse reporting on (`vim` with `:set mouse=a`, Claude Code).
2. Print or show a link (a URL, or an OSC 8 hyperlink).
3. Hold Ctrl (Cmd on macOS) over it, without Shift.

Observed: text pointer, no underline. Expected by the reporter: the link pointer, as in a plain
shell. In a plain shell step 3 already gives the hand (guarded by the tests above).

## Root Cause

`marked_link` returns `None` under mouse reporting without Shift
(`crates/micold-client/src/ui/material/terminal_pane.rs`, `marked_link`, per FR-016 and the
"Hover under a mouse-reporting program" edge case), and `pane_interaction` shows the hand only over
a marked link. So under mouse reporting the pointer needs Shift and Ctrl. The press is forwarded to
the program, which opens the link itself; the user cannot tell which text it treats as a link, and
Shift+Ctrl is undiscoverable. The code matches the spec: FR-007 and FR-016 said "link pointer only
while Shift and the link modifier are held".

## Decision (user, 2026-10-13)

Under mouse reporting, show the hand while the link modifier is held over a link, without Shift.
The click still goes to the program (G5); only the pointer changes. The underline and the address
hint keep requiring Shift (they claim the address the terminal would open, which is not true when
the program takes the click). Shift+Ctrl-click is unchanged (FR-013b, FR-016, G6).
