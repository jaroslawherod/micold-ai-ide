# Bug Report: SSH host alias remotes (git@github-alias:o/r) are not recognised as GitHub

**Type**: Spec conflict — FR-002 and research R5 rule out aliases on purpose, but an SSH host alias for github.com is the usual multi-account setup and git/gh work with it.
**Severity**: Medium — every GitHub feature (issue chip, issue-driven `create_worktree`, scoped credential, PR status) is off for such a repository.
**Feature**: 034-github-issue-worktree (FR-002, research R5 "URL forms accepted")
**Reported**: 2026-10-27 (issue #1475)
**Status**: Patched
**Patched**: 2026-10-27

## Description

`origin` = `git@github-micold:jaroslawherod/micold-ai-ide.git` with `~/.ssh/config` `Host github-micold` / `HostName github.com`. `create_worktree` with `github_issue` fails with "This repository has no GitHub remote."; the form's issue chip is disabled; the scoped credential reports no GitHub remote. `gh` and git work in the same checkout.

Reproduced on `origin/main` by reading: `GithubRepo::from_remote_url` (`crates/micold-core/src/github.rs`) accepts only host `github.com` (or `ssh.github.com` over SSH), so `choose_remote` returns `NoGithubRemote` for the alias. Confirmed by the pure-parser test `ssh_alias_elsewhere_or_unresolved_is_not_github` shape: any non-GitHub host yields `None`.

## Artifact Traceability

### spec.md
- **Affected requirements**: FR-002 ("a remote on any other host … does not [count]"); Assumptions line "only github.com is supported (FR-002)".
- **Gap identified**: FR-002 treats a host that merely names github.com through SSH configuration as another host.

### plan.md / research.md
- **Affected sections**: research R5 "Repository-local config only, raw URLs" (consequence: aliases not recognised) and "URL forms accepted" (an "unexpanded alias" is not a GitHub remote).
- **Impact**: SSH host aliases are now resolved with `ssh -G` at the points where the remote list is read; `insteadOf` remains unexpanded.

### tasks.md
- **False completions**: none (T0xx built what R5 decided).
- **Missing tasks**: T107, T108.

## Root Cause Analysis

Deliberate R5 decision, taken to keep the answer independent of where the daemon runs. It did not weigh SSH aliases, which are resolved by `~/.ssh/config`, not by git's `insteadOf`. Root cause: `from_remote_url` compares the URL's literal host; fix is a resolution step before it (`resolve_ssh_aliases`), keeping the parser pure.

## Recommended Fix

T107 regression tests (stubbed `ssh -G`), T108 resolution step wired at every site that reads the remote list or the push URL.
