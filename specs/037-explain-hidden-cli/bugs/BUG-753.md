# Bug Report: The row's CLI list hides unavailable CLIs and explains them only in a note

**Type**: Spec gap (the closed spec chose a different presentation than the one the reporter needs)
**Severity**: Medium
**Feature**: 037-explain-hidden-cli (issue #753, branch `fix/753_new-session-menu-show-full-ai-cli-provider-list`)
**Reported**: 2026-10-10
**Status**: Patched
**Patched**: 2026-10-10

## Description

GitHub issue #753, "New-session menu: show full AI CLI provider list, disable unavailable ones
with reason tooltip". The menu that starts a session and selects the AI CLI lists only the CLIs
that are available. An unavailable CLI is absent, so the user cannot tell it exists. Expected:

- the menu shows every supported AI CLI;
- an unavailable CLI is a disabled item with a red icon;
- hovering the icon shows a tooltip with the reason (CLI not found on PATH, environment-include
  off, startup script failed, and so on);
- a disabled item cannot be selected; available CLIs behave as before.

## Reproduction (on `origin/main`, from the code; the cited functions are unchanged since `1e3be384`)

1. Three supported CLIs, two available in a row's directory, one missing (any of the six states of
   037 FR-001).
2. Press the row's chevron. `session_start_menu_items` (`crates/micold-client/src/ui/mod.rs`)
   maps `State::offered_providers(dir)`, which is `known_clis(dir)`, to `MenuItem`s: only the two
   available CLIs are items.
3. The missing CLI is named only in a trailing note under the items (`start_menu_note`,
   `crates/micold-client/src/features/session.rs`, drawn by `MenuOverlay::note`), and only when two
   or more CLIs are available. With one available CLI and a missing default (033 FR-010) the list
   names no missing CLI at all.

## Root Cause Analysis

037 Story 3 and FR-010 were written as "name the CLI in the list", and the design (ledger D5, D6,
contract W4 surface U6) realised it as a note beneath an items list that is the available set.
Item visibility was never a requirement: 026 FR-006 only forbade a *selectable* unavailable
choice, and the implementation took "not offered" to mean "not drawn". Not an implementation error.

## Recommended Fix

1. `speckit-bugfix-patch`: amend FR-010, Story 3, SC-007 and the two Clarifications of 037;
   contract W4 surface U6; plan and tasks (Phase 8, T051 to T057, one milestone, `full`).
2. `speckit-bugfix-verify`.
3. Implement: the list shows every supported CLI in `AiCli::ALL` order; each unavailable CLI is an
   unpressable item with a red trailing `Icon::Unavailable` whose tooltip is `explain(&[cli], ..)`'s
   `{reason} {action}` (FR-012: from the answer that drew the list; without an answer's
   environment state, "`{name}` would not be found by a session here.", FR-002); the note and
   `start_menu_note` go.
