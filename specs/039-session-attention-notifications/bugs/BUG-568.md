# Bug Report: A window displaced from its project still reports its session in view, so attention events are lost

**Type**: Spec gap (Terms, *In view*, lists Settings as a screen that takes the main area over, but not
the read-only state of a window displaced from its project or refused it)

**Severity**: Medium (no notification and no unread mark for a session no window shows; an existing
unread mark is cleared)

**Feature**: 039-session-attention-notifications (Terms *In view*, FR-001, FR-002, FR-019; seam with
010 FR-024 and BUG-023)

**Issue**: #568

**Reported**: 2026-10-04

**Status**: Fixed (2026-10-05) — Phase 13 (T135–T136)

## Description

A focused window that another window took the project from (`Displaced`), or that was refused the
project (`Refused { ProjectBusy }`), kept reporting its selected session in view. The session service
then took that session as watched: its attention events were not counted, so no notification and no
unread mark, and since M4 the report also read it (`set_window_view` calls `mark_read`). The window
shows the takeover banner, read-only; the user is not looking at that session.

## Root cause

`State::view_facts` (`crates/micold-client/src/app.rs`) set `main_area_taken` from Settings only.
Whether the window holds its project is the binary's fact (`App::displaced`, `main.rs`) and was not
handed in.

## Artifact Traceability

- **spec.md**: Terms, *In view*: a window that does not hold its project is added to the
  not-in-view list.
- **contracts/wire.md**: no change. W1.6 keeps `WindowView` free of attachments, so the fix is in
  the client, not in `set_window_view`.
- **tasks.md**: T123 (`State::view_facts`) did what it claimed.

## Fix

- `State::view_facts`, `view_report`, `attention_on_welcome` and `attention_on_catalog_changed`
  take `impl Into<WindowFacts>` (`focused`, `holds_project`); a bare `bool` is a focused window that
  holds its project. `holds_project: false` sets `main_area_taken`.
- The shell passes `holds_project: !active_project_displaced(app)`. The report after every message
  then sends `in_view: None` on `Displaced` or `Refused { ProjectBusy }`, and the session again on
  the `Attached` that gives the project back.
