# Bug Report: Container sessions get none of the container's git env

**Type**: Implementation drift
**Severity**: High
**Feature**: 1002-sandbox-scoped-token
**Reported**: 2026-10-25
**Issue**: #1438

## Description
In a container daemon an AI session cannot use git against GitHub: `git fetch origin` fails with
`Host key verification failed` (no HTTPS rewrite) and no commit has an identity. The env set by
`podman create -e` (`argv.rs`: `git_env`, `HOME`) reaches PID 1's daemon only. The daemon the client
starts over SSH gets what `container_env` (`micold-client/src/daemon.rs`) forwards (data dir, image
reference, `TZ`, idle stop) and sshd's fresh `HOME=/home/node`, so its sessions have no
`GIT_CONFIG_*`, no reachable helper (`micold-daemon` is not on `PATH`) and neither `~/.gitconfig`.

## Artifact Traceability
### spec.md
- **Affected requirements**: FR-004 (git configuration shared as a sanitized copy; helper reset), FR-007 (HTTPS with the in-container helper, no SSH key needed).
- **Gap identified**: none in the spec; the code met FR-004/FR-007 only for the entrypoint's daemon.
### tasks.md
- **False completions**: none reopened. The wiring tasks tested the `create` argv, not the env a session receives. Fix tasks: T066-T068.

## Root cause
Environment set at `create` is not inherited by an SSH-started daemon (sshd builds each login afresh).

## Fix
At every session spawn (`env_hygiene` in `micold-daemon/src/supervisor.rs`, shared by PTY, shell and structured sessions), when the daemon runs in a container (`MICOLD_DATA_DIR` is the container data dir), add `git_env_with_helper(GITHUB_BASE, <current_exe, shell-quoted>)`, and `GIT_CONFIG_GLOBAL=<data dir>/gitconfig` when that sanitized copy exists (it exists only when *Git configuration* is shared). Spawning from the daemon uses `current_exe()`, so no build path goes stale. One `info` line per spawn names the variables set (names only).

## Follow-up (not in this fix)
`HOME`: the SSH-started daemon runs with `HOME=/home/node` while the entrypoint's has `HOME=$MICOLD_HOME`. #1434 (shared AI CLI sign-in ignored) has the same root cause and is handled in its own thread. `GIT_CONFIG_GLOBAL` makes this fix independent of `HOME`.
