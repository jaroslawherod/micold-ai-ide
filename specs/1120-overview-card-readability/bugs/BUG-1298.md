# Bug Report: Overview cards do not match the Overview Card Redesign design

**Type**: Spec gap and implementation drift. Issue #1120 named the design as its mockup
(`Mockup: https://claude.ai/artifact/3xzeTa9hKufvxuiqjGFWPs`), but the spec's **Input** left that
line out. Features 1120–1123 each built one piece from the issue's bullets. Nothing checked the
assembled card against the mockup, so the card drifted from it in frame, type, meta line, activity,
progress and pull request rows.
**Severity**: Medium. Nothing breaks, but every Overview card reads differently from the agreed
design, in both themes.
**Feature**: 1120-overview-card-readability (FR-001–FR-004, FR-007–FR-010, FR-019). The pieces from
1121 (expanded body), 1122 (issue link FR-002, FR-003) and 1123 (rows FR-004, FR-005, counts FR-006)
are replaced where the design differs, as 1120 already replaced 813's rules.
**Reported**: 2026-10-24 (issue #1298)
**Status**: Patched (FR-021–FR-028, T050–T058, milestone M5)
**Patched**: 2026-10-24

## Description

Issue #1298 says the Overview cards look different from the design's rows "Proposed" and "The other
states" (`bugs/BUG-1298/design.html`, copied from the artifact with every row's data). It asks to
list every difference at the design's card width and fix each one in the card's drawing. Behaviour,
keys, ripple and the context menu stay unchanged. The card's focus animation is #1299, not this one.

## Reproduction

1. Render the design: `node bugs/BUG-1298/shot.js <out>/d` (Playwright Chromium, a 1312 px viewport,
   `data-theme` light then dark). The five-column grid gives a card width of **243 px**. Each card is
   saved as `<theme>-card<i>.png`.
2. Render the app's cards with the same data on `origin/main` (3c7db2eb): append
   `bugs/BUG-1298/render_probe.rs` inside `mod tests` of
   `crates/micold-client/src/ui/material/overview_card.rs`, then run
   `PROBE_WIDTH=243 PROBE_OUT=<out>/r cargo test -p micold-client --lib render_design_cards -- --ignored`
   (headless `Mounted::drawn`, tiny-skia). It writes one PNG and one painted-text dump
   (`size@x,y "text"`) per card and scheme. The probe is never committed.
3. `python3 -I bugs/BUG-1298/side.py <out>` puts each design card above the app's card.
   Run on 2026-10-24, the result is `bugs/BUG-1298/main-vs-design-{dark,light}-{a,b}.png`: `a` is
   the "Proposed" row, `b` is "The other states" plus the pinned full-text card. In each image the
   design is on top and the app is below.

Every difference below shows in both themes.

## Root Cause Analysis

- `crates/micold-client/src/ui/material/overview_card.rs`:
  - `palette` (l.55–70) sets `body: r.surface_container_low`.
  - The card's `fill` container (l.522–532) has a border radius but no border width or colour (D1,
    D2).
  - The header (l.475–510) draws both clusters at `TypeRole::Label` with a `type_icon` glyph and
    `[spacing::SM, spacing::MD]` padding (D3–D5).
  - `collapsed_body` (l.701–754):
    - It stacks the title (`TypeRole::CardTitle`, weight 500 from
      `tokens::typography::OVERVIEW_CARD_TITLE`).
    - Then a branch row with the link after it (`row![branch, link]`), then a separate
      `text.sessions` line.
    - Then the activity in `on_body_variant`, the progress words above a `ProgressBar`, the rows,
      and the counts line from `text.prs`.
    - It uses `spacing::XS` between rows and `padding(spacing::MD)` (D6–D9, D11, D13–D15).
  - `pull_request_rows` (l.775–810) draws the number with `card_link`/`Text` at `TypeRole::Body`,
    a solid `Tag`, and words in `error` only when `failing`, else `on_body`. It also draws
    `"+{} more"` (D16–D19).
  - `expanded_body` (l.850–939) repeats the branch / sessions / progress / counts structure.
- `crates/micold-core/src/overview_text.rs`:
  - `sessions_line` (l.77–87) words D12.
  - `progress_row` (l.90–101) words the caption without "tasks" and with `Phase::label` "PR" (D14).
  - `CardText::of` keeps `prs` (the counts) beside the rows (D15).
- `crates/micold-core/src/issue_link.rs:90` labels a Jira key `Issue {key}` (D10, 1122 FR-002).
- Why: 1120's spec turned the issue's bullets into requirements but dropped its `Mockup:` line.
  FR-007 ("short branch on its own line"), FR-008 (a sessions line) and FR-001 ("the location type's
  icon and word") were therefore written from the bullets, not from the mockup. 1122 FR-003 then
  put the link *after* the branch, and 1123 FR-006 kept the counts line under the rows. Each spec
  was met as written, so no task is a false completion. The spec lacked the mockup's layout and
  conflicted with it in FR-001, FR-007 and FR-008.

## Recommended Fix

Drawing only, plus three text rules in the core:

- **Core**:
  - `overview_text`: a meta-line sessions phrase (D12), the progress caption with "tasks" and
    "PR phase" (D14), and no counts while the card draws pull request rows (D15).
  - `issue_link`: the bare Jira key (D10).
- **Client**:
  - `overview_card.rs`:
    - The frame: body on `surface`, a 1 px `outline_variant` border, 12/14 px padding and 8 px
      gaps (D1, D2, D6).
    - The header: a 13 px / 600 state word, the type word without its icon at 85 % opacity, 8/14 px
      padding (D3–D5).
    - The title at weight 600 (D7).
    - One wrapping meta line: link, monospace branch, sessions (D8, D9, D11).
    - The "NOW" label (D13) and the progress block, bar first and 6 px (D14).
    - Pull request rows: monospace underlined numbers, tonal pills, toned words, "+N more, hover
      to see" (D16–D19).
    - The expanded body takes the same pieces (FR-028).
  - Keys, ripple, the menu, focus order, link hit areas and the expansion rules are unchanged.
- **Snapshot and guide**: the covered states are regenerated, the showcase follows, and the user
  guide describes the meta line and the "Now" label.
- **Visual pass**: a side-by-side at 235 and 280 px in both themes.

Tasks T050–T058, milestone M5. D20–D23 are follow-ups (see the ledger).
