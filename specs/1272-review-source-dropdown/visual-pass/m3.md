# Visual pass — M3 (`MenuSelect` in the showcase)

Showcase (`micold-showcase`, tiny-skia on Xvfb, 1600×1000), Components section, `MenuSelect`
entry, light scheme. Screenshot: `m3-showcase-menu-select-light.png` (the stale, a-list and
many-pull-requests poses).

| Check | Result |
|---|---|
| Trigger: label left in `on_surface`, chevron right, outlined pill | pass (first render drew the fixed part in the button's content colour; fixed with `.tint(r.on_surface)`) |
| Open list floats over the line below, aligned with and as wide as the trigger | pass |
| Working tree option: chosen mark, highlight fill, Committed and Uncommitted chips inside the row | pass |
| Pull-request rows: state and check marks, `#n`, title; chosen one marked | pass |
| Many pull requests: list capped with its own scrollbar | pass |
| Long title ends in `…`, `#1290 · ` whole | pass (headless render, and `menu_select_fits`) |
| Poses in one row (`Layout::Inline`) pushed the third column past the page edge and shifted the triggers vertically | fixed: one pose per row (`Layout::FullWidth`) |

Near the window's bottom edge an open list flips above its trigger (`cdk::picker`'s rule), so it
can lie over the pose above while scrolling; that is the component's behaviour, not a defect.
Dark scheme: the same roles-driven drawing; `menu_select_fits` lays out every pose in both schemes.
