**Defect found and fixed (showcase fixture only).** In the first B18 run the coloured poses painted
colours four characters to the right of their tokens on context lines (`let rows` coloured `row`,
`view.finish()` coloured `sh()`). Cause: the showcase's diff literal used `\n \` line continuations,
which strip the next line's leading whitespace, so its context lines lost the four-space indent the
highlighted file versions (`BEFORE`/`AFTER`) have. The colours were right for the file; the diff text was
not the file's. Fixed in `showcase/sections/review.rs` (context lines written `\x20    …`); the re-run
shows every token coloured in place. The Changes view itself takes both from the same git state.
