# Bug Report: A container daemon's sessions run with the image user's HOME, so the shared sign-in is ignored

**Type**: Implementation drift (the entrypoint contract of research R3 assumed a home that sshd never passes on)
**Severity**: High: every Claude Code session on a container daemon with *Share AI CLI sign-in* asks to sign in again
**Feature**: 806-container-daemon-ssh-provisioning (branch `claude/project-thread-uwvq88`)
**Reported**: 2026-10-25. GitHub issue #1434. Same root cause as #1438 (git env; fixed separately).
**Status**: Patched
**Patched**: 2026-10-25

## Description

The shared `~/.claude/.credentials.json` is bind-mounted at `$MICOLD_HOME/.claude/.credentials.json`
(`/home/jaro/...`), but the daemon the bridge starts, and every session it spawns, runs with
`HOME=/home/node`, so `claude` reads `/home/node/.claude/`, finds no credentials and opens its login
flow. `HOME=/home/jaro claude auth status` in the container prints `"loggedIn": true`. The sanitized
`.gitconfig` and `sandbox-home` under `MICOLD_HOME` are not read either.

### Reproduction

On `origin/main`. Not run end to end (no container runtime in this environment); the mechanism is
checked in code:

1. `crates/micold-client/src/daemon.rs` `container_env` is the only environment the bridge
   (`argv::bridge_with_env`, `env K='v' micold-daemon remote bridge`) passes to the daemon. It names
   `MICOLD_DATA_DIR`, `MICOLD_IMAGE_REFERENCE`, `TZ` and `MICOLD_IDLE_STOP`, never `HOME`. The unit test
   `container_target_env...` (asserting `HOME` is `/home/jaro`) fails on `origin/main`.
2. sshd builds the login environment afresh, with `HOME` from passwd. The base image has uid 1000 =
   `node`, home `/home/node`. `packaging/basic/entrypoint.sh` rewrites that home to `$MICOLD_HOME`
   only when `/etc/passwd` is writable, and the published image predates it (#1287), so the login
   user's home stays `/home/node`.
3. PID 1 has `HOME=$MICOLD_HOME` (container `-e`), so `podman exec` looks fine, which hid the defect.

## Root Cause Analysis

sshd resets the login environment. The client forwarded only four container `-e` values, not the
home, and relied on passwd (entrypoint) for the rest. The home is the host user's home mapped by
`pathmap::map_for` (the value `MountSet::build` mounts credentials under and `argv::create` passes as
`MICOLD_HOME`), so the client can name it without asking the image.

Fix tasks T107 to T109 in tasks.md (Phase 15). T107 is the regression test.
