# Bug Report: A worktree whose issue is closed shows its branch instead of the issue's title

**Type**: Spec gap with a dependency issue. FR-015 asks for "the linked issue's title when the app
knows it", and the edge case *Linked issue unreadable or offline* falls back to the branch. Nothing
says what a **closed** issue gives. R8 reused `IssueLookup::read_issue`, the lookup 550 FR-007 built
for creating a worktree from an *open* issue, and that lookup rejects a closed issue even though
GitHub's answer carries its title.
**Severity**: Medium. Nothing breaks, but most cards of a busy project lose their readable title:
an issue is closed when its PR merges, while its worktree usually stays until it is deleted.
**Feature**: 813-worktree-overview (FR-015, edge case *Linked issue unreadable or offline*, research
R8, T057). The same title feeds 1120 FR-006 (card title), 1125 FR-011 (sidebar row) and 1126 (session
header) through `overview::State::known_title`, so all four show the branch.
**Reported**: 2026-10-27 (issue #1488)
**Status**: Patched
**Patched**: 2026-10-27

## Description

Issue #1488: worktree entries on the Overview and in the sidebar often show only a raw name such as
`feat/1439_basic-image-x11` instead of the issue's title. Expected: every worktree shows a readable
title, the folder or branch name only as a fallback.

## Reproduction (origin/main 728eb7238)

1. The label `feat/1439_basic-image-x11` is the **branch**, the card title's second choice
   (`micold_core::overview_text::card_title`: issue title, else branch, else display name). So the
   title of ticket 1439 was not `Known`.
2. The worktree directory is `feat-1439_basic-image-x11` (`naming::derive`), whose ticket is `1439`
   (`naming::ticket`), so the title *was* asked for: `shell/issues.rs` `request_titles` →
   `titles_to_fetch` → `on_title_remotes` → `read_title`.
3. Issue #1439 is **closed** (`state: closed`, closed 2026-10-27, read through the GitHub API).
4. `read_title` (`crates/micold-client/src/shell/issues.rs:980`) calls `GhCli::read_issue`, which maps
   `parse_lookup`'s `NotOpen { closed: true }` to `IssueLookupError::NotOpenIssue`
   (`crates/micold-core/src/github.rs:1470`). `read_title` turns every error into
   `TitleLookup::Unavailable` and logs "it is not an open issue". The query asked for `title` and the
   answer held it, but it is dropped.
5. The existing test `a_closed_issue_is_not_open` (`crates/micold-core/tests/github_issue_lookup.rs:74`)
   shows the same: a CLOSED node with `"title":"t"` parses to `Ok(Err(NotOpen { closed: true }))`.
6. `titles_to_fetch` never asks again for a ticket with an entry, so the card keeps the branch for the
   rest of the app run (R8: once per app run).

Checked and **not** the cause:

- Worktrees created after the Overview opened: `main.rs` `update` calls
  `shell::issues::on_worktrees_changed` whenever the worktree list's fingerprint changes or titles
  become readable (feature 1125 FR-011), so their titles are read.
- Worktrees the app or its MCP tool created carry the ticket in their directory name (`derive`:
  `{type}-{ticket}_{name}`), so `numeric_ticket` finds it.

## Root Cause Analysis

R8 picked the existing open-issue lookup to avoid a new GitHub read. That lookup's contract (550
FR-007) is "an open issue to create a worktree from", so closed issues, a normal end state for a
worktree's issue, come back as errors. The Overview needs only the title, which the same query
already returns for any state.

## Recommended Fix

1. `crates/micold-core/src/github.rs`: a title read that accepts any state, e.g. `parse_title(stdout)
   -> Result<Option<String>, IssueLoadError>` over the same `ISSUE_QUERY` answer (`Some(title)` for an
   OPEN or CLOSED issue, `None` for a missing issue or a pull request number), and an
   `IssueLookup::read_title(repo, number)` method whose default goes through `read_issue` (so
   `FakeIssueSource` and other test doubles keep compiling) and which `GhCli` overrides with
   `lookup_args` + `parse_title`. `read_issue` and its callers (worktree creation, the MCP tool) stay
   open-only.
2. `crates/micold-client/src/shell/issues.rs` `read_title`: use `read_title`; a `Some(title)` is
   `TitleLookup::Known`, `None` or an error is `Unavailable`, and the failure line still names the
   number only (FR-020).
3. Fix the `TitleLookup::Unavailable` doc ("offline, closed, no tooling" → no "closed").

## Out of scope (follow-ups, not this bug)

The issue also asks for titles when there is no numeric ticket (Jira keys, worktrees with no ticket)
or the lookup failed: fall back to a session title, the last commit subject, the PR title or the
spec's title. No spec asks for those sources; they are new behaviour (a feature). Two smaller gaps
seen while tracing, also outside this fix:

- A failed read (`Unavailable` after a transient error or a lost daemon) is never retried in the app
  run; R8 chose "once per app run".
- An included worktree whose folder carries no ticket but whose branch does (`feat/1439_…` in
  `my-folder`) never has its title read: `known_title` and `titles_to_fetch` look only at the
  directory name.
