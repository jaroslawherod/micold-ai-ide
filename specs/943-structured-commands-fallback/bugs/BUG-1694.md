# Bug Report: Clearing the structured view does not reset its state; earlier history still displays

**Type**: Spec conflict (the requirement was a decision; the user has reversed it)
**Severity**: Medium — `/clear` leaves the view looking as if nothing was cleared
**Feature**: 943-structured-commands-fallback (FR-005, US1 scenario 5)
**Reported**: 2026-11-05. GitHub issue #1694.
**Status**: Patched
**Patched**: 2026-11-05

## Description

After `/clear` in a structured session the transcript still shows every earlier turn above a
*Cleared* marker, each headed "Before the clear". The user expects the view to start empty after a
clear.

### Reproduction (on `origin/main`, by reading the code and its tests)

1. Build a transcript from a history of two turns, then a `ConversationReset` (fixture
   `command-clear.jsonl`; `crates/micold-core/tests/structured_transcript.rs`, the era tests at
   ~1738 and ~1849 assert exactly the old behaviour).
2. `Transcript::entries()` returns the two turns, then `Cleared` (`era 1`).
   The window draws all of them; `era_tag` heads the user turns "Before the clear".

## Root cause

Not a defect: the code follows the spec. FR-005 and US1 scenario 5 required the turns before a
`/clear` to stay visible, marked (`research.md` R5: entries carry `era`, bumped at each `Cleared`;
the window draws earlier eras as "before the clear"). The product decision was reversed by the
user on 2026-11-05 (option B of the #1694 escalation): a `/clear` resets the view.

Code that implements the superseded requirement:
- `crates/micold-core/src/structured/transcript/build.rs:192` (`ConversationReset`): bumps `era`
  and opens `Cleared`, keeping every earlier entry.
- `crates/micold-core/src/structured/transcript/{mod,entry}.rs`: `era`, `Entry::era()`.
- `crates/micold-client/src/features/transcript_selection/shown.rs` (`BEFORE_THE_CLEAR`,
  `era_tag`), `crates/micold-client/src/ui/transcript/{entries,mod}.rs` (`user_label`,
  `latest_era`, the `lazy` key's era tag).
- `docs/user-guide/worktrees-and-sessions.md:1787`.

## Decision on the open details (minimal reading)

- The transcript drops every entry before the clear; the held **events** stay (the composer's
  history recall, FR-025, and the rebuild from events are unchanged, so a rebuild gives the same
  cleared view).
- The *Cleared* marker is kept as the first entry: it already exists, costs nothing, and tells
  the user why the view is empty.
- No scrollback or toggle for the dropped turns.
- `/compact` (FR-004) is unchanged: its turns stay visible.
- `era` and the "Before the clear" label have no remaining use and are removed.
